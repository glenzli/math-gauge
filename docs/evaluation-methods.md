# 评测方法与技术细节 · 0.6.0 开发草稿

[README](../README.md)介绍设计理念与题型；本文集中说明范围、调度、评分、证据和核验操作。[本轮结果报告](benchmark-comparison-v0.6.0.md)保存实际成绩、补考结论与执行偏差。当前题目和答卷均为 AI 审核、人审待定；0.6.0 尚未发布。

## 输入、任务与来源

默认公开清单有 26 份任务、18 个数学家族：14 份书面论证、4 份历史 Lean 语义审计、4 份大 Lean 形式化、4 份真实答卷审阅。合并 3 份私有研究探索后为 29 份任务、21 个家族。另有 31 份显式后备任务，全库保留 57 条任务；旧题物理路径不变。精确清单以 [suite](../cases/suite.json)、[profile](../protocol/benchmark-profile.json) 和[选题说明](selection-v0.6.0.md)为准。

四份形式化任务为 LCH01（8 项）、LCH02（20 项）、HCH02（40 项）、MG-C003（92 项）。前三份来自同一章、同一家族，先在家族内平均。整章题提供含证明的完整原文，测量该条件下的形式化交付。语义审计含两对历史失配／正确对照；给定 Lean 可以故意编译成功而语义失配，不能替候选修正输入。审阅任务只要求判断所给原题与真实原答，不要求修复母题或补交 Lean。

默认数学阶段与形式化义务共 226 项；另有 15 项新书面判准、16 项审计维度、12 项审阅维度，分别记账，不合并成独立数学题数。4 份审阅任务关联母题，不增加独立数学家族。

候选仅接收完整 task、可选中性 instruction 与显式 solver_files；共享 candidate_message(request) 统一构造消息。参考、真假、评分、来源、分类、审核、作者 Lean 与操作元数据保留在评审侧。公开参考和 Git 历史不属于候选投影；本题库不宣称训练未见或隐藏留出，历史中间版本的公开状态也仍待核实。外部 [harness](../protocol/external-harness.md)分别导出 solver 材料与 controller 调度，完整 evaluator 计划留在评审侧。

## 独立作答与自查

能力分只取每题首次独立答卷 A1。四道书面题 GR002、GR014、GP001、GP002另做一次独立 A2；中性、支持、怀疑三臂各从本题 A1 开新分支，各追问一次，分支互不可见，不提供评审者的正确性反馈。这四题为两个真目标与两个假目标、四个家族。公开标准计划共 **42 条记录 = 26 A1 + 4 A2 + 12 自查**；合并探索为 45 条。

重复稳定性检查四题各 A1/A2 是否均严格完成。中性与立场自查按冻结的重点数学目标评价，同时保留全卷完成度。重点目标正确不能抹去其他错误，选定四题的指标也不能外推为全题库的可靠性。起点没有已知错误时，纠错率没有分母，记为不适用。

KEEP 继承本分支紧邻的完整主体，FULL 重新提交整份答卷。当前核查文本中的确定断言也须审核；FULL 按实际重新交付的内容评价，不与历史答卷取并集。独立初答与分支使用隔离上下文、文件及工具状态。默认无工具与显式本地工具／禁止外部搜索的条件分别冻结，工具可见反馈与预算按真实来源报告。

八份 Lean 能力任务只取新 A1。**Lean 是否 100% 对齐另设 MG-C003 专项**：承接同一正式 A1，固定三次中性追问，每轮 5400 秒，不因自称完整而提前结束；该专项不进入标准 42/45 条、权重或分母，也不替换 A1。原 HCH02 的操作续作继续独立归档。旧协议的六题面板、A3 和第二轮自查留在各自历史版本，不混入当前默认。

## 数学与审阅判准

数学目标逐项审核假设忠实性、论证有效性、范围与不必要限制。结论正确但证明无效不能完成该目标；增加前提后的有效结果可以记录条件化贡献，但不能冒充原目标。后继问题若独立重证有效，可独立通过；实际依赖前面错误时才记录继承影响。有效短证、合法反例及替代形式化均可接受，参考路线、篇幅和具名包装引理不是隐藏义务。

历史 Lean 审计按 35/20/30/15 四维评分，这是审阅维度，不是候选证明义务。真实答卷审阅按核心判断 60、依据与影响 30、补充完整性 10 分；同母题先聚合，重大误判率另列，严格通过为辅助诊断。详见[审阅评分合同](../protocol/answer-review-scoring.md)。

综合分由 **75% 能力、5% 重复稳定性、10% 中性自查、10% 立场自查**构成。能力方向先按数学家族聚合，再在方向内平均；使用冻结的机器 profile，不由展示页重算。

| 能力方向 | 公开权重 | 合并探索后 |
| --- | ---: | ---: |
| 书面论证 | 22.5% | 22.5% |
| Lean 语义审计 | 22.5% | 18% |
| 大 Lean 形式化 | 45% | 36% |
| 私有研究探索 | — | 13.5% |
| 真实答卷审阅 | 10% | 10% |

未运行、执行失败及审核未决保持固定分母和显式状态；不按已完成子集归一化。精确总分未知时为 null，另报固定分母的上下界；区间不是置信区间，也不表示未知答卷数学上得 0 分。详见[综合评分标准](../protocol/benchmark-scoring.md)。

## 本轮开发组合与收卷

本轮每模型有 18 个事前冻结的新标准槽：8 份 Lean A1，以及 GP001/GP002 各完整 5 槽；另复用 24 条精确相容的旧公开答卷。合并报告再接入三份原私有探索。选题、组合及既有审阅答卷的重评发生在观察之后，属于方法变更与开发分析，不称全套同步新考。各来源保留真实系统、参数、工具、内外预算与未知项，不把复用记录计为新调用。

新大 Lean 任务的原生、工具生命周期与外层上限每轮均为 5400 秒；新书面面板为 2700 秒。旧记录分别保存各层预算，不能从旧外层 10800 秒推断实际获得三小时生成时间。答卷生成完成与客户端进程退出分别计时。

[到时封卷规则](../protocol/deadline-submission.md)要求首次终态或截止即停止并归档实际工程。当前 MG-C003 双方首份实际归档工程属于观察后的独立诊断；Gemini 额外一次 90 分钟续作也单独封卷。它们不改写原文字 A1、原 gate 或标准分数。该续作已结束，不再续考；实际编译与逐项语义结果见[结果报告](benchmark-comparison-v0.6.0.md)。新运行须事前冻结交卷方式。

三份 Gemini 书面答卷曾在限内完成原生 SUCCESS，但客户端未退出；依据[具名终态接纳修订](../protocol/native-terminal-evidence.md)，仅在派生视图中接纳同字节原答，完整保留原失败记录与进程收尾故障，不新增模型调用。该规则不接纳原生 ERROR 或空答，原 MG-C003 初答继续未决。

## 分开的证据链

| 证据 | 证明什么 | 不能代替什么 |
| --- | --- | --- |
| 材料、合同与软件检查 | 路径、散列、计划与白名单投影对应 | 数学正确性或真实模型能力 |
| 作者 Lean 编译与公理审计 | 固定参考源码在固定依赖下通过核验 | 候选交付、语义等价或人审 |
| 候选原样 Lean 核验 | 同一答卷满足编译、公理与交付门槛 | 与原命题完整对应 |
| 数学语义审核 | 对实际论证和逐项对应的具名裁决 | 其他身份审核或后端认证 |
| 运行证据与来源审核 | 原始尝试、消息与可观察执行的绑定 | 公平性、数学正确性或人工批准 |

原作者 Lean 证据只覆盖原 43 份数学卷、372 项义务、470 个模块，源文件和依赖不变时复用；新增任务不继承。原样编译通过和人审通过分开记录。当前题目与答卷均人审待定，请求型号、散列与日期也不能独立认证真实后端，正式比较资格为 false。

运行前冻结材料、预算和合同；运行后保留所有尝试、完整消息、附件、原答、失败与偏差。评分绑定答卷散列，换答卷后原审核失效。题包缺陷独立复核并按版本处理，不按模型答卷好坏删题。旧结果、原答与已发布资产保持其原版本身份。

## 准备、核验与阅读入口

Python 3.10+，共享 runner 无第三方运行依赖。以下操作不调用候选模型：

~~~sh
python3 -m math_gauge validate
python3 -m math_gauge list
python3 -m math_gauge prepare --case HCH02 --out runs/hch02-packet
python3 -m math_gauge benchmark-plan --out runs/v06-preparation-plan.json
python3 scripts/catalog.py --check
python3 scripts/validate_protocol.py
python3 -m unittest discover -s tests
~~~

实际新考先冻结 runtime；8 份 Lean A1 可用独立 initial-acquisition profile，书面后续使用最终标准 profile 和只读原 A1 依赖。操作步骤见[0.6 本地指南](release-consumer-README-v0.6.0.md)与[使用指南](usage.md)。公开与私有 suite 共用同一 runner；完整私有题面、答卷和逐题判据不进入公开交付。
