# 评测方式与证据状态

一次可复核评测需要固定题目与评分义务，完整投放候选材料，保存原始运行证据，再对绑定同一答卷的数学与交付作逐项审核。共享 runner 校验合同、身份和审核记录；数学正确性仍需实际审阅论证。

当前 43 份新试卷尚未运行模型。以下区分已经存在的单轮及题组能力、已保存的旧实验，以及尚待实现验收的多轮规格。

当前GR001为0.1.2，其余40题组及两章为0.1.1。GR001的[数学范围修订](../drafts/progressive-groups-20261030/reviews/strict-amendment-0.1.2.json)与0.1.1编辑清理分别记录；其新AI复查不冒称重复独立复核。本轮审查结果见[严格数学复核](../results/strict-review-20261030/README.md)。

## 先固定测什么

旧单题轨包含确定性证明或反例、语义对齐及探索构造。当前递进题组包含书面论证、Lean 对齐审计、生成和修复；整章题要求完整 Lean 工程及逐义务映射。每份答卷只承担 task 明确提出的数学与交付义务，书面审计不会因统一说明而额外承担 Lean 生成要求。

递进题组以一个完整组为样本，必须完成全部必答阶段。整章分别有 34/92 项义务，但仍是两份试卷。阶段、共用母题、同一答卷的后续版本具有相关性，不能按独立题相加。整章提供原文证明，结果应按该形式化条件解释。

运行前冻结题面、参考、rubric、合同、允许附件、版本和工具预算。后续澄清另立版本，旧答卷和旧成绩继续绑定原字节。不能根据候选答案新增评分义务或选择性保留样本。

## 候选输入与实际隔离

`case.json` 的 `solver_files` 是候选附件白名单，参考、来源、真假、rubric、合同和审核是评审材料。题面保留完整数学条件、必答范围与源码交付约束；分值、通过门槛、预期答案和实验机制留在评审侧。

使用共享 `candidate_message(request)` 发送完整题面和附件。`prepare` 只导出候选材料，不启动模型；只发送 `prompt.md` 可能漏掉必需 Lean 或章节附件。公开目录可读不表示候选在本次执行中应有读取权限。

材料目录分离不等于进程访问隔离。实际闭卷运行须核验文件、网络和工具边界，并保存实测收据。工具条件发生变化时保留偏差及所有尝试；曾有搜索的答卷不能改称闭卷，也不能混进无检索样本。

## 数学审核与严格完成

审核记录绑定 `response_sha256`，逐项检查条件忠实性、证明有效性、范围正确性及是否不必要地缩小结论。结论猜对但论证无效不通过；一个正确旁支也不能抵消原目标的错误声称。

参考提供充分的证据路线，允许有效短证、不同反例、合并定理和替代构造。除非 task 明确要求某构造，不能把具名参考引理当成唯一解法。新增条件后的有效结果可记为条件化贡献；把新增条件改称原题条件则是漂移。

题组严格通过要求所有必答阶段通过；阶段权重只描述完成情况，不能抵消漏项。后题若能独立重证，可以通过；若实际使用错误前提，则记录根错误和继承关系，不能把一个共享错误算成几十个独立推理失败。

服务未交付、环境故障、格式缺失、Lean 失败、诚实未完成、数学错误和审核未决分开。题包疑有缺陷时另行复核版本处置，不悄悄移出计划分母。逐项字段与门槛见[题组协议](../protocol/question-groups.md)。

## 两条 Lean 证据链

| 作者参考 | 候选交付 |
| --- | --- |
| manifest 固定 task、reference、rubric、COVERAGE、源码、工具链和依赖 | 从冻结答卷提取原始完整源码，保留文件与字节位置 |
| 固定 profile 下编译声明闭包并审计公理 | 在受限环境中无修补编译完整项目并审计全部实际声明 |
| 覆盖账本说明已经形式化的数学范围及缺口 | 通过声明必须对应本答卷的实际义务，整章另核验 alignment.json |
| 不能替代候选结果或人工审定 | 编译通过仍须逐项核对自然语言语义 |

作者默认 profile 是 Lean 4.29.1，P001 另有 Lean 4.36/TauCeti 固定 profile；版本和确切依赖见[参考验证器](../scripts/formal/README.md)。不混用 profile，不把源码旁旧缓存当作当前结果。

候选生成/修复及整章任务要求完整命名源码、合法公理与真实语义对应。整章还须交统一入口与全部义务恰覆盖一次的 `alignment.json`；冻结背景不能被同名源码覆盖，未完成义务不能被审核抬为通过。执行器核查声明实际存在与收据绑定，不自动证明映射的数学等价。

原版 40 题有完整作者主任务 Lean 证据，P003 为部分覆盖。新增题组不能继承旧题的完整覆盖；两章背景编译也不能充作目标章编译。当前新增目标的完整作者 Lean 核验仍待完成。

## 重复作答与两轮自查

新协议计划每模型 43×3=129 个独立初答槽位，再对八题从同一 A1 开中性、支持、怀疑三个分支，各两轮，增加 48 个槽位，共 177。当前实际调用为 0，不能填造成功数或把未运行写成 0% 通过率。

八题与重点断言、四真四假、全部48条后续消息均在看到答卷前固定。三个分支不互相读取，A2/A3不进入分支；不把真值、参考、编译反馈或审核传回候选。它测定点、无正确性反馈的自查及无论据立场影响。

复核轮用 KEEP 保留紧邻上一版的主体，用 FULL 重新交付完整答案；每轮仍需审核新主张。协议区分整组严格完成、整组数学及重点断言数学三种维度，保留 A1→R1→R2 轨迹，分别解释纠错、损伤、补全和服务故障。

上述材料已经冻结，但共享 runner 还没有经过验收的多轮调度与 KEEP/FULL 组合入口。实际启动前仍需在同一 runner 中完成离线实现与验收，冻结后端、预算、顺序及传输策略，并另有执行授权。详情见[执行协议](../protocol/reliability-execution.md)和[材料包](../protocol/reliability-20261030/README.md)。

## 工程检查证明什么

在仓库根目录可运行以下材料和软件检查：

```sh
python3 -m unittest discover -s tests
python3 -m math_gauge validate
python3 -m math_gauge validate --suite drafts/progressive-groups-20261030
python3 -m math_gauge validate --suite drafts/chapter-exams-20261030
python3 exercises/refresh_catalog.py --check
python3 protocol/reliability-20261030/validate_materials.py
```

`validate` 检查文件合同、来源登记和候选投影，不能裁定证明。原版其他三个 suite 的命令在[使用指南](usage.md)。`refresh_catalog --check` 继续核对原 41 题固定目录；材料包 validator 检查43份题面、消息和版本关系，不调用模型或 Lean。

需要指定工具链/依赖的真实 Lean 测试在普通环境会跳过，须按原记录报告，不能写成编译通过。[现有题组工程证据](../drafts/progressive-groups-20261030/validation/README.md)保存132项测试、117通过及15跳过，以及一项随后单独通过的真实隔离合成工程检查；它没有编译新题完整参考，也不是实际模型成绩。本次文档导航改写不重新认领这些检查为新运行。

## 已有结果与复算

原 41 题完整比较、R005 单题补测和历史校准各自冻结，不拼接为一次实验，也不回填旧分数。当前旧结果是 AI 审核暂定比较，题目和答卷人审待定；新43份没有成绩。解释和分母见[结果与版本](results.md)。

[离线复算](usage.md)重新核对档案散列并汇总保存的审核，不重新判断数学、不调用模型、不重编 Lean。档案保留原 runner；维护当前源代码不会替换冻结实现。复算一致不能代替人工确认。
