# 评测方法与证据

一次可复核评测先冻结题目与评分义务，完整投放候选材料，保存原始输出，再对同一答卷作逐项数学和交付审核。共享runner核对合同、身份和审核绑定；数学正确性仍需实际阅读论证。

## 输入与运行

`cases/suite.json` 是唯一当前题集，默认命令覆盖全部43份。每题 `case.json` 使用 `path_base="case"`；task、参考、rubric、合同及附件源路径均相对所在题目目录。分类与机器导航由[目录生成器](../scripts/catalog.py)维护。

候选只接收task、可选中性instruction与显式solver_files。适配器通过 `candidate_message(request)` 发送完整附件，不能把题号、track、来源、真假、分类、评分或审核元数据扩展成提示。目录分离不提供进程访问隔离；实际闭卷运行须核验文件、网络和工具边界，保存所有尝试及偏差。

## 数学与严格完成

逐项审核条件忠实性、证明有效性、范围正确性及是否不必要地缩小结论。猜对真值但证明无效不通过；有效的条件化贡献单独记录，不能回填原目标。参考路线不排除有效短证和替代构造。

题组严格通过要求全部必答阶段通过，权重只表示完成情况。后继阶段若独立重证正确，可以通过；若实际依赖错误前提，则记录根因与继承影响。共享错误不能算作许多独立推理失败。

完成分先按完整试卷归一化，再平均三次初答和同类试卷；四类能力分默认各25%。综合分为70%能力分加各10%的三次严格全对、中性重点正确性、立场下重点正确性。重叠考察重点不重复加权；严格整卷通过另列。精确值未确定时显示null及保守区间，部分执行不改变计划分母。公式与选择范围见[综合评分标准](../protocol/benchmark-scoring.md)。

服务未交付、环境故障、响应格式、Lean失败、诚实未完成、数学错误和审核未决分开。疑有题包缺陷时另作版本处置，不悄悄移出计划分母。

## 分开的证据链

| 证据 | 证明什么 | 不能代替什么 |
| --- | --- | --- |
| 软件测试与材料校验 | 当前程序合同、路径、散列与输入投影 | 数学正确性或模型能力 |
| 作者Lean真实编译与公理审计 | 固定源码在固定依赖下可验证 | 自然语言等价、候选交付或人审 |
| 作者逐项语义审核 | 指明目标与声明的实际对应、覆盖和缺口 | 真实人工批准或模型结果 |
| 候选Lean核验 | 原始答卷提取的同一工程满足编译、公理与交付合同 | 数学语义等价 |
| 数学审核与人工审定 | 各自身份下对实际论证的裁决 | 其他身份的审核 |

作者证据账本记录43/43份完整覆盖、372/372项义务及470个已编译模块；MG-GP003的S5已完成任意域的实际转移几何和原典范单位证明。现有源码与依赖未变时，可通过[证据核验器](../scripts/formal/check_evidence.py)复查冻结身份，不把复查称为本次重编译。详见[验证状态](verification.md)。

生成/修复及章节题的候选通过须有原样完整源码、真实编译、公理审计和逐义务语义审核。整章另需Main.lean与恰覆盖全部义务的alignment.json；冻结背景不能被同名源码覆盖。作者参考不能替代候选工程。

## 重复作答与后续分析

计划为43×3个独立初答，加八题×三分支×两轮，共177槽位/模型。八题、重点断言与48条消息在看到候选答卷前固定，各分支只读自己的历史，不接收评分、参考、真假或编译反馈。

KEEP继承紧邻上一版完整主体，FULL重新提交整份答卷。分析分别使用整组严格、整组数学和重点数学三个维度，保留A1→R1→R2全部轨迹、纠错、损伤、补全及未决原因。规则见[执行协议](../protocol/reliability-execution.md)与[评分标准](../protocol/reliability-scoring.md)。

共享runner提供同主计划分片执行、历史绑定、KEEP/FULL重建、逐轮审核、运行资格和固定权重聚合，离线验收见[运行器证据](../verification/runner/README.md)。[运行证据标准](../protocol/execution-evidence.md)要求保存实际返回信息、隔离材料、全部尝试和具名来源审核；文件散列通过不等于外部来源已认证。原始材料和追加审核快照可追溯，自查继承的A1/R1也须具有相应运行资格。

本版实际后端、预算及运行授权仍未冻结，候选模型调用为0。程序可以对证据充分的运行开放正式资格；当前没有这样的真实记录，题目也仍待人工审定，因而没有正式成绩。
