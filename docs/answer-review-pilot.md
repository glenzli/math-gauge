# 真实答卷审阅

真实答卷审阅从既有公开母题的真实答卷中选出4份完整材料，测量模型能否判断实际写出的数学断言、给出依据并说明缺陷影响。它自0.4.0纳入默认公开基准，在本地0.5.0继续保留，并沿用同一runner；独立清单 [`cases/answer-review-suite.json`](../cases/answer-review-suite.json)仍可用于单独选择。审阅合同为0.2.0，题目、参考、判准和来源见[完整目录](../cases/answer-review/README.md)。本文件是当前正式说明入口，文件名保留既有链接。

## 选材与样本边界

材料来自 Gemini 3.8 Flash High 历史开发执行：MG-GR104 初答、MG-GR014 怀疑分支第二轮、MG-GR010 初答及 MG-GP003 初答。请求型号与预算是历史声明，来源散列不独立认证服务端后端。原执行的报告见[Gemini综合结果](gemini-combined-2026-11-03.md)。两种候选模型各有4份已归档审阅答卷，共8份；它们按新版判准重评，结果以[当前对比报告](benchmark-comparison-2026-11-03.md)为准。

选材保留一个整体有效的对照、一个正确主结论与有效证明并存但带额外错误断言的核查、一个错误识别与有效替代路线并存的答卷，以及一个定理范围被扩大后破坏必答证明的答卷。具体裁决必须由新参考中的完整论证支持。旧母题的通过或得分不等于答卷每句话都正确，也不能直接作为本组的答案。

4份审阅任务与4份母题直接关联，且共享历史执行来源。样本单位是一份完整答卷的审阅，不把阶段、发现或替代证明另计为独立样本。同母题先聚合，再汇总审阅方向。本地0.5.0保留这四份AR及其母题GR104、GR014、GR010、GP003；默认26份数学交付加4份审阅共30任务/21数学家族，合并3份私有探索为33任务/24家族。五对默认Lean交付共享家族，不能沿用早先把每份交付都当独立家族的计数。原43数学卷加3份同族加强稿为46数学卷，与4份AR共50条任务；新增AR或加强稿不制造对应数量的新数学家族。当前是本地0.5.0预览，已发布0.4.0及更早资产保持原样。

## 候选输入

4题使用同一简短题面：判断所给答卷在原题条件下是否正确、完整，并给出可核查的数学依据。题面不揭示正确与否、错误类型、位置或数量；也不把评审判准逐项写成候选提示。

| 候选文件 | 内容 |
| --- | --- |
| `materials.md` | 解释各附件的材料关系 |
| `original-task.md` | 完整原题，保留全部结构、量词、定义域及交付条件 |
| `original-answer.md` | 完整原始答卷；MG-AR002 为本轮 `KEEP` 继承的完整初答正文 |
| `current-check.md` | 仅 MG-AR002：本轮原始 `KEEP` 核查答复全文 |

MG-AR002 同时审阅继承正文和本轮核查中实际作出的断言，不能只交一份 `KEEP` 短答而遗漏正文。该分支原先收到的立场反馈不作为本次审阅者的指令；`KEEP` 仅说明历史材料如何继承。

原题中的“请证明”“全部阶段必答”等要求属于待审材料，供判断原答是否完成其任务；本次候选只须审阅，无需重新完成整套母题、补全原 Lean 或提交新 Lean 源码。参考、评分、原作者模型标签、选材分类、既有结果和审核记录均不在候选白名单内。

原题与原答使用原始 UTF-8 字节直接复制，不删节、改错、拼接新错误或润色。中性附件名及独立的材料说明不改变原文字节。每个 `provenance.json` 记录母题版本、公开来源、逻辑归档路径、原答与输入绑定、完整文件字节数和 SHA-256，并核对规范导入与最终归档中的答卷相同；MG-AR002 另记录 `KEEP` 的正文来源、本轮答复及已有原生最终答复提取回执。该轮传输文件还带有工具专用的空 JSON 块和外层换行，候选原样保留已归档的最终答复文本，传输文件与提取关系另行绑定。归档路径不含本机绝对路径，完整执行目录与未选用材料不进入本组。

## 准备、执行与审核

无需新依赖。在仓库根目录执行：

```sh
python3 -m math_gauge validate --suite cases/answer-review-suite.json
python3 -m math_gauge prepare --suite cases/answer-review-suite.json \
  --case MG-AR002 --out runs/answer-review-ar002
```

输出目录必须尚不存在。`prepare` 只生成本题候选文件与 `request.json`，不调用模型。适配器应使用共享 `candidate_message(request)` 传递完整附件；仅发送 `prompt.md` 会漏掉待审原题与答卷。

现有8份审阅原答及执行记录已经保留，本次重评不调用模型、不改写答卷。未来新增执行仍应先冻结模型、预算与条件，再按[现有运行接口](usage.md)建立新目录。通过 `run` 留存原始审阅答卷后，继续使用共享审核接口：

```sh
python3 -m math_gauge review-template --run runs/answer-review-run \
  --out runs/answer-review-reviews.json
python3 -m math_gauge review --run runs/answer-review-run \
  --input runs/answer-review-reviews.json
python3 -m math_gauge report --run runs/answer-review-run \
  --out runs/answer-review-report
```

生成模板后，由具名评审者按各题新参考与判准填写，再应用审核。评分绑定本次审阅答卷的响应散列。`assumption_fidelity`、`proof_validity`、`scope_accuracy`、`unnecessary_restriction` 和具体发现继续分别记录；评审者须保存有效证明与真实缺陷的边界，不因正确结论忽略明确错误断言，也不因一条错误路线抹去其他有效论证。

当前每题100分，由核心判断60分、依据与影响30分、补充完整性10分构成。这是审阅维度，不能当作母题阶段或Lean义务。共享runner按冻结的审阅合同记录与汇总；同母题先聚合，避免增加同源变体就提高其权重。AR占能力分10%，重大误判率单列，严格通过仅作辅助诊断。完整定义见[审阅评分合同](../protocol/answer-review-scoring.md)。

参考允许有效替代论证与有据新发现；参考中的修复方向供评审理解，不要求候选重新证明母题、修复原答或提交Lean。核心判断、证据有效性、影响范围和补充完整性分别裁决，不能因结论正确忽略明确错误依据，也不能因一条错误路线抹去另一条完整有效论证。

AR纳入、60/30/10判准及权重是在观察这批结果之后作出的方法变更。现有8份原答统一按新规重评，原评分和证据保留；当前结果应称为重评与合并重算，不能冒充事前冻结的新考试。本地0.5.0公开计划共54份记录，合并私有探索后57份；审阅目前不补做重复或自查。当前整体另含三份同族书面题的新原生初答，其余相容答卷复用，不是全任务同步新考试；此处AR原答重评不增加候选调用。新版0.3多轮合同只用六题A1/A2及各臂R1；旧A3/R2退出默认但保留原始材料，MG-AR002引用的历史R2原答及KEEP核查也不改写。

## 审核状态

4题及当前答卷仍为 **human pending**。AI起草、数学复核、执行记录与人工批准分别记录；已有8份候选审阅答卷，不再标为未运行。母题Lean编译与覆盖仍只属于母题，不能作为新审阅任务的形式化证明或人工批准。工程校验与图表生成不构成额外模型能力证据。

每题还在 `evaluator/original-reference.md` 原字节保留母题完整参考，明确排除在候选白名单之外。它的旧生命周期、未跑模型等文字是历史原文，相对链接按原母题目录解释；当前审阅题状态以新 `review.json` 为准。
