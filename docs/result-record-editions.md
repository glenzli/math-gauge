# 新测记录与既有答卷的来源版本

Benchmark1.0.0的题目、评分政策和已发布兼容清单保持原字节。旧答卷继续放在`results/v0.6.0/`，真实1.0.0新运行放在`results/v1.0.0/`；`benchmark.json`通过`selected_result_source_versions`明确登记新增模型的来源版本。未登记覆盖项时仍使用原兼容路径，不猜测最新目录。

记录顶层的`benchmark_version`表示实际执行题包；评分报告的版本字段属于其绑定的原评分政策。二者分别核验，不为对齐标签改写原政策或报告。

旧方法迁移记录保留真实0.8.0政策与全部六种旧成绩视图。实际按1.0.0新测、首次采用聚合0.9.0的答卷使用私有`first_assessment_source`，与`score_history`互斥：绑定原首调用前冻结、首次派发，以及冻结提交中的评分政策原件。离线Git对象链核实原政策与当前政策相同；缺少这条完整来源链不能获得历史豁免。公库仅保留不透明源散列，不公开含私有题路径的冻结原件。来源证明是事后整理，原冻结时点不改写。

若该原提交中的执行profile仍内嵌旧方法标签，则另绑定同一Git树中的profile原件，严格核实只有聚合、MC及提交来源三个组件版本字段不同，题目、权重和数学判准完全相同。这证明实际执行profile的身份，不代表曾产生旧方法成绩。

当前提交来源评分直接使用已核验的正常最终答卷与三轮实际返回。工程封卷、原答文本、KEEP继承和编译证据分别绑定；不把工程树散列当成原答散列。正常最终答卷与所核实的工程义务必须对应；只有输入传递、封卷与来源接口适配，原数学审核及共享评分算术不变。

AGY订阅运行的物理请求和有效尝试分开计数。`math-gauge.agy-manuscript-request-history/v3`逐次绑定原生收据、原结果、原冻结和纯系统故障的具名接纳证据。未确证为纯系统故障的失败仍消耗有效尝试；选定首次正常交卷后停止。旧请求历史合同的校验规则保留。

完整性检查沿用[正式记录合同](../protocol/result-record.md)、[提交来源](../protocol/submission-scoring.md)及同一共享评分器；新增来源版本不构成重新判卷或新的benchmark分数。
