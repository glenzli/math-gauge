1.3.0 是本地开发预览。初始预览只重算既有证据；后续经用户授权的实际批次和非数学 canary 分开留档，流程检查不充作真实题目成绩。当前已发布题包及 1.0/1.1/1.2 榜单不变。新增私有题已在独立登记册中登记；登记不是公开授权，也不修改封版套题。

主排行榜显示整体交付率和 SMC、RMC、MC。分类排行榜内，独立开放研究与书面证明、Lean、辅助研究并列，每类可切换图表和表格、独立选择排序口径。独立开放研究显示整题三分，类内满分 100，占总榜 10 分。证据缺口保留未知区间，真实 0 分正常显示。原版本选择器可以切换 1.3.0、1.2.0、1.1.0 和 1.0.0。[本地总榜](../site/index.html?edition=1.3.0)

现有17个模型的原分项按30／30／30重算已确认贡献。新题满分10分，独立评审后按配置纳入已确认贡献，未结算部分保留在完整区间内。柱状图使用固定100分框架。三种新版整体视图为显式综合构造，原MC/RMC/SMC定义及其1.2源数据保留。原逻辑39题加新题为40题。固定交付为39项原初答＋3轮Lean自查＋3轮独立开放研究，共45次。正常final计交付，缺少旧运行原件时保留未知。各模型选定的中性续答集合另列。

新指南复用1.2的全部细节：题型/子类、家族聚合、书面与Lean及研究边界、作答流程、三分定义、原80/20中性续答和三轮自查；在其中加入新题与30／30／30／10，避免要求读者另读旧版。各版本原始答卷、评审和下载保持原路径；1.3的派生综合JSON另存 `site/versions/1.3.0/`，不改旧下载。

数学品味考察 R1、R2 的研究主线和 R3 对实际成果的核查与取舍。研究能力核验三轮的实际成果，包括深化、修正和证明闭合。早期有效成果继续作为证据，后轮推翻或收窄按实际真值及范围处理，重复内容只计一次。

公开目录保存通用代码、版本政策、合成测试数据及已采用的脱敏分数。实际题面、正文包、私有独立评审键、参考、三轮原稿和逐稿证据保留在私有工作区。展示生成器读取公开基准和通过检查的聚合字段。原基准来自 `site/data.json` 的 nonlogical_retry_3 三口径，保留原精度、SMC 排序及源 SHA-256。

## 分数与两层聚合

价值评审修订 0.2.0 在三个口径中都以 1:2 汇合数学品味 T 与研究能力 C，题分 `Q = (T + 2C) / 3`。主榜以同一口径计算 `S = .30W + .30L + .30R + .10Q`，W、L、R 分别取书面、Lean、辅助研究的原百分制分项。1.2 的三种分数保留原始定义和数据。[版本参数](../protocol/mathematical-taste/v1.3.0/value-policy.json)

T 的 MC 按价值 60 分、结构与条件判断 20 分、自审取舍 20 分评正面信用，RMC 再扣有原稿证据的错误根。评审检验研究结论的实际增量和前提。清楚限定范围的有限维成果可以获得信用，局部偏离经后轮修复也可保留严格品味通过，早轮已确认的错误仍在 RMC 计入。C 的数学判断、MC/RMC 和五项检查沿用原选定来源；原 SMC 也完整保留在原采用层。[原三分来源](../protocol/mathematical-taste/v1.3.0/score-modes-results.json)

严格信用修订 0.1.0 将检查点通过率与 SMC 分开。SMC 使用同一份成果和同一套满分预算，只保留经严格验收的净 RMC 信用。全项通过时保留 RMC，不能自动得到 100。存在未通过项时，将原 MC 信用和已有错误扣分按成果归属分账，再剔除未通过项的剩余信用；不得对已剔除的错误重复扣分。T 使用原 60/20/20 预算，C 的五个信用块各上限 20，分账总和必须精确保留原 MC/RMC。旧评审没有细分时，新分账明确标为来源绑定的新 AI 判断，不冒充恢复历史细分。

因此新题各分项及题分满足 `SMC ≤ RMC ≤ MC`。检查点仍显示通过数和未决数，例如 C 的 4/5 是验收覆盖，不是自动 80 分；全项通过另列诊断。检查未定保留相应信用的固定上下界，不按已知部分重新归一。分项仍按 1:2 汇合，`completion_v130` 直接读取主榜 SMC。此修订不追溯改写 1.0/1.1/1.2。[严格信用参数](../protocol/mathematical-taste/v1.3.0/strict-credit-policy.json)

独立开放研究题最多贡献总分的十分。新总分相对旧基准可增可减。缺组件、未测和证据不足保留固定区间，`exact` 为 `null`。确认未正常交付时整题 RMC 和 SMC 为 0，逐项数学判断仍待证据。本组件目前缺少可采用的 MC 截止成果证据。运行归因缺失时保留未知。

采用的配置在三个总分均有确值时参加 1.3 总榜的完整范围比较。其他配置显示已确认贡献和未知区间，名次留空。两个分项合成一道题，题分按 10 分权重计入总榜一次。

## 独立能力轴

|---|---|---|
| 数学品味 `mathematical_taste` | 80% 本题品味 SMC（严格通过的实际信用）＋20% 六个旧命题拓展家族按严格标准复核的百分制品味分 | 第十轴，旧题证据随画像阶段切换 |

| 数学深度 `depth_v130` | 80% 原 depth + 20% C | 结合原阶段深度与本题成果 |

| 开放研究能力 `open_research_v130` | 80% 原 open_research + 20% C | 旧基底使用五家族，新证据取本题核验的研究能力 |
| 严格完成度 `completion_v130` | 两个阶段共用同一 1.3 主榜 SMC | 与画像阶段选择独立 |

数学品味分别显示已判定的新题检查数以及旧题有确值的家族数。新题品味 SMC 由严格验收的净成果信用计分，保留未定检查造成的区间。旧题严格复核也保留未决区间。真实 0 分照常显示。

自主拓展 E0、E1、E2、E3 分别取得新机会权重的 0、1/4、1/2、全部。E0 表示三稿已评且未发现可核实的域外成果。评审未决保留这 20% 的画像区间。档位只参与研究主动性。

数学画像可切换雷达图、按轴排名和表格，共用模型与首答／含续答选择。按轴排名使用所选维度的确值，区间和未知另列。链接保留所选视图、维度、阶段和模型。

1.3 的榜单数据与模型下载提供 `independent_research_abilities` 字段，严格信用修订使用 `math-gauge.independent-research-abilities/v6` 合同，并保留原 v5 兼容。`first` 和 `revision` 分别读取原首答和含续答基底，并共用本题的已核验结果。`independent_taste` 保留品味 RMC，`independent_taste_smc` 保留品味严格净信用，检查计数另存；`autonomous_extension` 保留档位和机会覆盖。缺少 1.3 正式 SMC 时，完成度保留未知。模型下载只包含该模型的画像。[画像参数](../protocol/mathematical-taste/v1.3.0/profile-policy-v2.json)

旧题严格复核按六个家族等权，从取舍价值、条件与范围、证明支持三个维度评 0–100 分。答卷即使没有另证新定理，也按实际选择的表示、条件、主张和证明核验评分。严格复核的审查份数与可评分份数分别列示，原文缺失或数学核验未决保留未知。含续答阶段只对正式选中的同父续答逐家族使用 80% 首答和 20% 续答。免测家族沿用首答评审，未采用续答的配置只有旧题首答证据。[严格复核政策](../protocol/mathematical-taste/v1.3.0/legacy-taste-strict-policy.json)

`scripts/assess_legacy_taste_strict_v130.py` 核对严格评审与既有答卷、原评审及逐字引文的绑定。`--out` 制备待核对的阶段汇总，`--apply` 本地采用，`--check` 从原件复核。旧评审与原汇总保留，严格汇总缺失时第十轴保留对应未知权重。新来源只供第十轴使用，题分、总榜分和分类分沿用原公式。公开数据保留阶段分、覆盖及不透明来源散列。实际 AI 评审身份与上下文在私库留存，人工审核待完成。

## 离线三阶段协议

交接工具为 `python3 -m math_gauge.taste_v130` 的 `check-case`、`reveal`、`seal`。当前独立评审使用 `python3 -m math_gauge.independent_research_review` 的 `template`、`check`，显式绑定评审补充及完整三轮；旧交接组件的评审接口保留原冻结实现，不用于本批采用。参数见 `--help`；精确私有路径与操作步骤仅见私有操作说明。

1. `check-case` 核对固定题面、材料、规则、评审键、来源及共享工具文件的 SHA-256。当前本地工具以工作区文件散列绑定，可在不提交的情况下验证；后续任何工具修改都会使登记失配，需重核并刷新绑定。没有伪造一个已提交的运行版本。
2. `reveal R1` 要求全新参与者树和独立评审档案树；仅复制白名单材料、通用规则和本轮提示。后续提示留在私有源树。
3. 操作者在同一新求解会话收集首个正常 final，停止本轮写入；提交原始 operator observation，原文和显式交付附件逐字冻结。`seal` 使用排他创建、原文 SHA-256 与前轮 seal 哈希链。修改、换会话、提前下发、重交、第四轮均拒绝。失败或未决边界另存，不伪造正常 final，且阻断后续轮。
4. 前轮冻结后才允许下发下一轮；不给评价或额外反馈。全部三稿保留并逐稿核验，研究能力看完整轨迹，不取最好稿、不盲拼不同条件的结果或补入未交付内容。
5. 独立评审在不同上下文进行；逐稿、逐门槛和总轴判断均留原字节引用。结构检查不代替数学真伪核查，AI/fixture/人工分别标记，fixture 不得改名成真实模型评审。私有轨迹由 seal、observation、raw 和显式附件描述符组成，不进入公开展示投影。

**隔离限制：本工具是离线材料交接与证据冻结工具，不是执行器或操作系统沙箱。** 目录分开和 prompt 禁令不证明候选无法读取同一账户的其他文件、会话或网络。真实开测前必须由外部 harness 建立独立新上下文、同一求解会话、文件/网络权限及时间/费用控制，并保留实际证据；本地 fixture 只证明白名单导出和冻结流程。工具不启动模型、外部进程或网络，也不生成 CLI/native 执行收据。运行时证据缺失不得由固定目录名、散列或操作者声明推断补全。

若采集在 seal marker 落盘前中断，已写原件不覆盖，下一轮不放行；操作者先检查原始 observation、已写字节与哈希，再决定恢复，不能清理后当成新首稿。源损坏直接失败，不网络拉取或偷偷回退。

## 经授权的批次与逐配置采用

后续用户已授权本地提交及当前榜单十个 GPT 模型和推理强度配置的新题测试，包括 Sol6.1、Sol6.2、Astra6、Astra6.2、Terra6.1 各 Max／xHigh。首场完成核验后，余下配置四路并行。独立 Sol6.1Max 评审可与考试并行。本地提交和运行证据分别使用指定的历史 Git 时间及实际时钟。

实际执行属于[独立执行组件](independent-research-execution.md)，与上述离线交接组件分开。只有当前CLI和精确源码哈希下的实际系统正负探针、新上下文、工具能力及模型服务检查通过，才允许发送真题。无模型目录查询、空线程或合成canary不冒充题目作答；canary使用量单独保留。完整三轮只接受各轮首个正常final和当时明确交付的文件，不发第四轮，不取最好稿，不拼入未经核验或未交付的内容。

原采用层由 `scripts/adopt_independent_research_batch.py` 和 `scripts/adopt_independent_research_score_modes.py` 生成。价值修订使用 `scripts/adopt_independent_research_value.py`，通过 `--replay-root` 从归档读取选定原评审、MC 补审和三份封卷，通过 `--reviews` 读取每配置的 `review.json` 和 `notes.md`。`--out` 写入仓库及来源树之外的全新临时提案文件，`--apply` 原子安装，`--check` 从原件复算并核对已安装字节。生成器自动读取存在的 `value-results.json`。待评的 T 与自主拓展保持未知，C 继续读取现行已选来源。公开索引只含合计、档位和不透明来源哈希。此次复核只复用已有答卷。

严格信用层使用 `scripts/adopt_independent_research_strict_credit.py`，传入同一 `--replay-root`、`--value-reviews` 和私有 `--allocations`。它核对原选定合同、MC/RMC、检查点、三封卷、新分账及逐字引文；`--out`、`--apply`、`--check` 的本地边界与上述相同。新的 `strict-credit-results.json` 只保存两轴严格分上下界和不透明来源散列，不覆盖 `value-results.json` 或原三分索引。榜单 v4、画像 v6 和下载共用此层。复算、采用、导出均不调用候选。

索引绑定固定1.2原字节、版本政策、原计划名单、已采用子集及私有来源的不透明哈希。榜面显示已采用数占计划数的比例。其他配置的新题继续留空，保留已确认贡献与未知区间。完整三口径可比较的配置才列新范围名次。旧版数据和下载继续保持原字节。
