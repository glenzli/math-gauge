# 证据留存与恢复

当前留存组件为 `evidence-retention 0.1.0`，适用于公私仓库。它只改变证据的存放方式；benchmark 1.0.0、题目、所选答卷、原审核、六种成绩视图与发行资产均不变。

## 当前目录保留什么

- 当前模型的正式记录、完整最终答复及原始自评、有效审核和审核更正链。
- 交付工程的数学源码、入口与对应表，以及判断正常交卷、截止、工具权限和有效尝试所需的摘要。
- 计时、token、缓存、计价与价格来源；当前成本明细继续使用独立的成本证据目录。
- 当前题包、政策、发行兼容记录和公共安全投影。

同字节副本、旧快照、完整原生事件流、原始大包及编译器/依赖缓存不再反复铺在当前目录。它们仍按原字节保存在已提交的 Git 历史中。`results/evidence-retention/v0.1.0/index.json` 为每个原逻辑路径登记 SHA-256、字节数、原文件权限、固定源提交、源路径与 Git blob；相同字节共用一个对象描述符。

原记录中的路径和散列保持不变。评审工具可据索引直接读取本地 Git，不会在原目录悄悄还原文件，不联网取回缺件，也不会用历史副本掩盖当前文件损坏。需要按目录检查的旧封卷在一次性的临时目录中物化，结束即清理。被封卷的嵌套 `.git` 只作为显式登记的原始数据读取，不能充当运行器的 Git 配置。

这次先补齐了此前仅存在本地的原件，再建立索引。补档回执保留实际补档时间及观察后性质；不将新入 Git 的时间写成原执行时间，不改变交卷认定。

## 核查与恢复

完整审计需要通常的 Git 克隆及本地历史对象。仅复制当前文件、浅克隆或省略历史对象的打包不构成完整证据副本；缺少对象时工具会明确失败。公开库只恢复公开材料，私库必须单独获得访问权。

从公库根目录检查全部登记对象的原字节：

```bash
python3 -B scripts/retain_evidence.py check --deep
python3 -B scripts/retain_evidence.py check --root ../math-gauge-private --deep
```

查看某个逻辑路径实际绑定的提交和源文件：

```bash
python3 -B scripts/retain_evidence.py where --prefix results/v0.6.0/<model>/<record>/originals/answer.md
```

恢复指定目录供人工检查时，必须给出仓库外、尚不存在的目标目录：

```bash
python3 -B scripts/retain_evidence.py restore \
  --prefix results/v0.6.0/<model>/<record>/source-packages \
  --destination /tmp/math-gauge-source-inspection
```

私库恢复使用相同工具并加 `--root ../math-gauge-private`。恢复只写入检查副本，不执行原包内的脚本。原始分片包应先恢复其整个目录，再按其原清单恢复容器。时间、费用和数学审核工具使用共享读取层；候选者导出不包含这个索引、Git 历史或评审读取能力。

## 后续留档

先将唯一原件提交，再绑定固定源提交。只有来源已提交、原字节已核验且不承担当前数学阅读用途的文件才可进入冷存。`prepare` 根据经过审核的计划建立新索引；`prune` 再次核验所有对象及当前副本，仅删除已登记、未修改的受 Git 跟踪副本。它不清扫未跟踪目录或其他用户文件。

当前目录节省的容量不等于 Git 历史缩小；同一内容的重复路径本来就由 Git 共用 blob。本次没有改写历史、重新评分或调用候选模型。两库的整理数量与校验摘要分别记录在各自的 `results/evidence-retention/v0.1.0/audit.json`，完整路径由本库索引提供，私有路径不进入公库。
