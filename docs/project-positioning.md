# 项目定位

Math Gauge 测量数学任务在实际给定条件下是否完成、自然语言目标与Lean声明是否对应，以及模型能否审阅真实写出的数学答卷。正确结论需要有效论证；在更强前提下成立的结果不能自动完成较弱前提下的原目标。

当前为**本地0.6.0草稿 / human pending，尚未发布**。题材涵盖分析、代数、拓扑、范畴与几何；评审保留原有假设、量词、定义域与结论强度，不补入分离性、完备性、统一界或全局提升条件。九项[考察重点](../cases/by-focus.md)是交叉阅读索引，不是九个独立能力分。

当前结果按四题归档工程的来源审核0.4.0及分类聚合0.8.0／Strict0.2.0留档，保留原初答、真实执行状态和全部规定自查轮次。详见[结果与来源](results.md)、[记录合同](../protocol/result-record.md)和[当前预算](../protocol/c003-180-budget.md)。

## 让问题在合适的结构里变得可解

本项目借用格罗滕迪克《Récoltes et Semailles》中的“泡核桃”（浸泡坚果）比喻：通过周围理论的成熟，让原先难以打开的问题逐渐显出入口。出处与译引见 Colin McLarty 的 [The Rising Sea](https://www.landsburg.com/grothendieck/mclarty1.pdf)（引原手稿第552–553页）。寻找简化问题的空间、对象和表示，是本项目的数学取向；具体成绩仍根据所交论证与原目标的对应关系判断。

作者[《AI，数学能力，与未来》](https://glenzli.com/notes/ai-mathematical-ability-and-the-future/)将Lv1描述为既定对象与规则下的计算、执行和实现，将Lv2描述为既定定义、公理、语言和问题框架内的证明或反驳。这是能力种类的区分，不是价值或难度排名；解决前沿猜想也可以属于Lv2。Lv3提出有生产力的问题，Lv4创造新的数学框架，不能简单用“题目更难”代替。

这一代题包从与OET写作、审计和形式化有关的工作中，抽样检查一定程度稳定的Lv1/Lv2能力。独立解决前沿未解问题不作为准入门槛；题包也不穷尽Lv2或认证Lv3/Lv4。当前三轮Lean对齐自查只提供一个相关案例的有限观察。模型若找到正确的短证或更合适的表示，应获得对应完成分；若改变表示，需要交付足够的对应证明，让结论确实回到原问题。

## 当前范围与样本

默认公开基准包含24份相关任务：8份书面论证、4份历史Lean语义审计、4份形式化、4份真实答卷审阅、2份命题拓展和2份背景核查，共20个数学家族。当前工作树仅保留选定题目，旧题及备选题通过Git历史恢复。合并4份私有书面论证、4份命题拓展及2份背景核查后为34份任务、30个家族。精确清单以[suite](../cases/suite.json)、[profile](../protocol/benchmark-profile.json)及[0.6选题说明](selection.md)为准。

形式化为LCH01的8项、LCH02的20项、历史HCH02的40项及原MG-C003的92项。前三份共享CH2家族，先家族内聚合，不能作为三个独立家族重复加权。历史审计含两对失配/正确对照，以35/20/30/15四维审阅，不增加候选Lean生成义务；历史中间版本的公开可得状态尚未核实，不能据此称隐藏留出或已公开历史发布。

每份完整题组或整章是一份相关样本；阶段、义务、重复作答和自查版本不能拆成独立试题。默认数学阶段/形式化义务共190项，与15项原书面判准、6项公有研究档位判准、16项语义审计维度和12项AR维度分开记账。4份AR按来源母题家族聚合；当前母题独立证明退役后，四个审阅家族仍各保留一次。维度、来源原答与审阅不拆为额外独立样本。

整章题提供含证明的完整原文，测量该条件下的形式化交付，不测未提供证明时的独立发现。审阅题提供完整原题与真实原答，只要求审阅其中实际作出的断言，不要求重新完成母题或补交Lean。

## 分项与解释范围

统一公开＋私有题池，公私只列数量：书面证明35（书面论证25／论证审阅10）、Lean35（语义审计10／形式化15／对齐自查10）、数学研究30（背景核查10／研究稿完善10／命题拓展10）。命题拓展6题占10分，只计无提示A1且原题错误扣分，背景核查公2／私2已建，研究稿完善仍0题。主值为已核实贡献／100，当前已建90分，剩余10分待建，完整总分未知，不重新归一化。[分类与评分](../protocol/benchmark-scoring.md)和[机器政策](../protocol/scoring-policy.json)定义精确合同。

默认每题A1，公开24／合并34个初答；C003另固定连续三轮“是否100%对齐”自查，独立计10分，复用同一数学题，不增加独立家族。A2、书面中性和立场分支退出默认计划与计分；固定档案中旧42／45条来源输入及所有原返回保留，不当作当前默认槽数。

分项保留逐项完成度，Strict整题全部实质要求满足才通过；Strict的自查也评整段轨迹，要求最后92项全对齐、三轮交付与诊断准确、无误报和回退。后续工程不回填初答，不取最好一轮或证明并集。审阅按核心判断60、依据与影响30、补充完整性10，先父家族聚合；重大误判率另报，Strict整题判断进入该模式的审阅子类。

部分等价测项按题文及实际回答方式相容性复用旧答，保留每个来源的系统、参数、工具、预算和未知项。DeepSeek沿用用户确认的原0.3条件并合并实际补交材料；未知原生事件与时序不由整理补造。分类和方法均为观察后修订，不是全套同步fresh考试，不提升人审、后端或运行认证资格。独立非逻辑重跑含初次最多3次，仅无交付故障可用，初次和重跑两条件分别留档。

## 证据与当前状态

当前仅保留用户选定的[最新固定记录](../results/README.md)，历史结果与旧配置通过Git恢复。题目与答卷均待人审；作者Lean、候选编译、公理审计、数学语义对应、执行来源审核及人工批准分别记录。当前保留题的作者证据为6份原始数学卷、122项义务和160个模块，新增范围不继承其覆盖，也不能用作者证明替代候选交付或人审。

完整合法反例、有效短证、不同构造和替代形式化均可完成对应目标，参考路线和篇幅不是隐藏义务。诚实未完成、错误论证、交付缺失、环境故障与审核未决分别报告。四道形式化题以选定初答阶段的归档工程审核数学完成度，原答与原生执行记录分别留存，详见[工程审核](formalization-audit.md)、[终态证据说明](../protocol/native-terminal-evidence.md)和[到时封卷规则](../protocol/deadline-submission.md)。

参考及Git历史继续公开，供透明复核；它们不属于候选输入，本题库不宣称隐藏留出或保证训练未见。请求型号、日期与散列不能独立认证实际后端。正式比较需核实运行真实性、公平性、题目与答卷的人审及适用的Lean门槛；当前正式资格为false，不具备认证排名资格。

所有公开与私有任务共用runner。候选只接收白名单题面、附件和允许的本分支历史；外部harness分开保存solver、controller和evaluator材料，私有题、答案、判据及逐题结果不进入公开ZIP。所有正式测试均允许本地工具与预置公共依赖，禁止联网检索和工具联网；允许使用和实际使用分别记录。独立无工具组退出固定留档，不作为当前工具组的首答。

当前0.6.0仅为本地草案；已发布[v0.4.0](https://github.com/glenzli/math-gauge/releases/tag/v0.4.0)及更早资产、原答与旧审核保持不可变。本地准备、检查与导入不调用候选模型，也不表示已发布新任务包。
