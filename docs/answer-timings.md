# 逐题耗时留档

各固定快照旁的`answer-timings.json`是独立时间附件，版本0.1.0。它绑定原记录、当前选定原答和时间来源；追加附件不重写原答、原评、原记录或数学成绩，也不触发候选调用。公开附件只含公开题逐项记录与公私合并统计，完整来源及私有逐题记录留私库。

每个附件保留39道初答和C003规定三轮。时间缺失、尚未运行、无最终交卷、审核未决分别记录。缺失时间为null，不能用0、规定时限、其他题或其他轮次补齐。计时不认证后台型号或实际隔离状态。

## 计时口径

| 标识 | 含义 |
|---|---|
| native_terminal_wall | 实际作答运行启动至首次原生终态，包含工具与模型服务等待，排除其后CLI清理及评审编译 |
| execution_elapsed | 原运行器记录的整次执行耗时，可能包含退出收尾 |
| historical_reported_elapsed | 从历史输出或已绑定摘要恢复的当次执行耗时；保留原字段，不升级为独立运行认证 |
| coordinator_observed_wall | 派发记录至协调者观察完成的间隔，包含观察误差，非精确原生运行时长 |
| operator_reported_elapsed | 操作者交回的耗时摘要，缺少可独立校验的原生计时事件 |

时长由原数值字段或带时区的原始起止时间计算。原生终态和CLI退出均在时，优先首终态。评审者编译、公理审计、文件修改时间、归档时间、尚在运行时的临时快照及其他答卷的耗时不进入正式单题时间。

## 历史恢复与证据

历史来源须与当前选定答卷SHA一致。保留用于提取的原始输出片段、原事件和会话身份及实际提取字段；时间为旧运行声明时明确标记。原会话可能包含其他工作，档案不因此复制整段对话。找不到有据来源的项目继续缺失。

首次、规则选定尝试、纯系统失败和模型失败仍沿各自原始接纳规则。主统计使用当前选定正常交付的初答时间，不取最快轮次、不把各次重试合并成一次作答。能取得的物理尝试时间另存于附件；未知的历史尝试次数或时长不补造。C003三轮单列，不能混入39道初答中位数。

## 汇总与比较

附件同时列出已交卷、计时齐全、缺时间、无交卷及未运行数量。中位数、平均值、已知最短／最长与累计时长仅基于有时间的选定正常交卷；失败时长另列，累计时长不等于并发运行的日历用时。不同模型覆盖不同题目时，总表是现有记录的描述统计；按同题配对的比较需另列共同题数。

“最大值”指已记录题目的最长耗时，是未齐全模型实际全题包最大值的已知下限；不预测缺题最大值，不以运行上限充作观测值。

公私附件复核，不调用模型：

```sh
python3 scripts/answer_timings.py --private-root ../math-gauge-private
```

已有数学记录与评分按原流程独立核查。附件收集是观察后的元数据整理，不改变人工数学审核状态。
