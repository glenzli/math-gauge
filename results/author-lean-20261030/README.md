## 如何验收一题

1. 读取当前完整task、候选附件、reference、rubric和contract；这些字节与本批开始前的`6a6338f133ee312d8905ea9066f92dda14543e51`一致。
2. 读取该题`formal/alignment.json`。每个阶段或章节义务都列出真实Lean声明、假设、量词、定义域、结论、表示、依赖和缺口；`COVERAGE.md`给出易读说明。
3. 展开源码中的定义并核对定理类型。特别检查逆向、同一个见证的量词顺序、实际商/极限/函数空间与题面对象之间的桥、反例的全部前提，以及前序加强条件是否被带入后项。
4. 查看`formal/manifest.json`、`verification-report.json`、`declarations.json`及`logs/`。本地模块都由固定源码在新的隔离输出中编译；原题的旧olean或兄弟题输出不作为本题证明。公理闭包只允许`propext`、`Classical.choice`和`Quot.sound`。
5. 查看本目录`semantic-reviews/`中的独立审核。其身份和源码散列由账本单独绑定；审核者不等于该题作者。作者自述、独立AI审核、内核检查与人工批准分别保留。

每题的`formal/`都是出题侧文件，不加入候选附件白名单。对于故意语义错配但可编译的输入，原候选源码保持不变；作者工程证明判定或修复的正确性。整章作者工程同时保留冻结的跨章定义依赖及逐项原文对应。

## 复核身份与重编

只检查保存证据的身份、一致性和覆盖计数，不调用模型或Lean：

```sh
python3 results/author-lean-20261030/check_evidence.py
```

它复用共享作者验证器，逐题校验冻结输入、显式模块、审计源码、alignment、编译报告、所有保存日志、声明清单和独立审核散列，再与账本比较。数学正确性仍须阅读真实题面和证明；该命令不会自动建立语义等价。源码改变后旧报告及旧审核失效，不能只刷新账本取得通过状态。

需要重新编译时，按[共享验证器说明](../../scripts/formal/README.md)使用该题manifest与新的输出目录。通常使用Lean4.29.1/Mathlib`5e932f97dd25535344f80f9dd8da3aab83df0fe6`；GP001使用显式固定的Lean4.36.0-rc1/TauCeti profile，不与其他题混用。依赖精确修订、编译器散列和直接导入缓存身份均保存在逐题报告中。

本批[工程与材料校验](validation.json)记录168项测试的151项通过与17项可选环境跳过，以及六个suite、候选投影和目录检查。真实作者编译以逐题报告为依据；测试数或声明数不表示题目数、数学难度或模型通过率。跨题复用的模块和声明在逐题总数中重复计数。
