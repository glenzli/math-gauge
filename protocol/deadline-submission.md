# 到时封卷 · v0.1.0

Lean 工程题以首次原生终态和事先冻结的绝对截止时间中较早者封卷。超时即停止候选写入，收取当时已有的工程，不继续等最后一条文字回复。首轮完成度与后续修复能力分别报告，后续版本不覆盖首轮。

这里的原生终态须绑定本轮生成，不能与CLI进程退出混同。若完整成功结果早已在限内存在而进程拖尾，答卷完成与客户端清理分别记账；具体条件及原始失败记录的保留方式见[原生终态证据](native-terminal-evidence.md)。

本规则由用户在查看本轮运行后提出。本次对 MG-C003 两个模型的首份实际归档工程同等实施，属于 **观察后的交付方式修订**；不是原考试事前已冻结的规则。原始文字、原生状态、超时、交付门、旧审核和原 response 分数全部保留。机器描述见 [policy](deadline-submission-policy.json)。

## 收卷与评分

1. 每轮启动前冻结题文、附件、数学义务、工具与三层预算、入口、收卷方式和截止时刻。新运行的四档大 Lean 工程均采用到时封卷；书面题和语义审计不因此增加工程交付义务。
2. 首次终态或截止触发后，先停止候选及其写入进程，再对工程作稳定性检查、冻结完整清单与字节。记录实际触发、停止和采集时刻；清理或采集耗时不成为继续作答时间。父调度器异常退出也须收卷，不能把仍在变动的目录当冻结证据。
3. 全量归档允许的工程文件。评分源码固定取根目录 `Main.lean` 及其实际本地 import 闭包，另取该快照的完整 `alignment.json`；未引用的探索、备用和检查文件仍归档，不能择优充当入口。实际导入的辅助文件也不能被排除。必交入口、对齐表或闭包缺失，记交付不足，不能从零份目标得出通过。
4. 保留配置及固定依赖身份，编译原字节并审计公理，不运行候选脚本或下载依赖。禁止用缓存、后续轮工程、评审反馈、作者实现或另一模型答案补交。编译成功与逐义务语义通过分别记录。
5. 只对实际提交的有效贡献给完成度；未完成项留在固定分母内。没有有效交付记本轮交付失败，不能据此声称所有数学命题均错。没有最终文字不自动抹去已合法封存的工程，也不能把封存工程伪装成模型原始文字。
6. 后续中性自查或明确授权的补时，各自再封一卷。首轮、每轮自查和额外补时保持独立版本，不取最好一版替代首次答卷。达到补时上限仍无有效交付，记该次续作失败，不自动循环重试。

## 当前记录与可复现边界

当前回溯范围仅 MG-C003 的 Terra、Gemini 正式新 A1：采用各自首份已存在的实际归档快照，不从后续轮挑选。若原截止瞬间没有快照证据，只能称“首份归档快照”，明确停止到采集的延迟或未知项，不能重建或宣称精确的截止瞬间状态。

Gemini 额外一次 5400 秒是用户授权的操作续接，仅继承其自己的允许工程及可见上下文；原首轮零字回复没有可伪造的 assistant 父答。续作获给完整原题与原附件，无评审结论。它不是 fresh A1，不替代首轮，也不补写原三次中性专项的执行历史。

本次工程审核使用独立 `forced-workspace/v0.1.0` 来源，分别报告交付、编译和语义三轴。原生响应散列与工程清单散列并列；若共享编译器需要文本载体，评审者生成的源码投影必须明确标为技术投影，其散列不得冒充原始响应散列。此来源目前作为具名诊断轨保存，不由共享 importer 自动改写标准 42/45 条的 response 结果或资格。以后若将工程来源纳入综合评分，须在新的固定 profile 中事前选择双方的来源与分母；不得混入旧报告而沿用原实验身份。

所有结果仍区分 AI 审阅、真实编译与人工批准；本轮 human pending，formal comparison eligibility 为 false。规则调整不改变任何数学目标或已发布资产。
