# 递进题组与整章考试合同

本协议增补既有 evaluation.md；不追溯改变原41题、既有答卷或成绩。`drafts/progressive-groups-20261030` 将原题逐一扩为新版本题组；`drafts/chapter-exams-20261030` 包含卷1第2/3章整章形式化。它们沿用同一个 runner。

当前题面0.1.1通过编辑等价记录衔接0.1.0数学复核；旧文件和审核不被覆盖。task只保留数学目标、全部必答范围及交付约束；分值、整组通过规则、预期答案与判卷提示留在评审合同及[评分标准](reliability-scoring.md)。全题三次独立作答和八题的两轮自查遵循[执行协议](reliability-execution.md)，当前只准备材料，没有模型运行。

## 出题范围与条件连续性

每组至少五个必答阶段，保留母题完整最弱条件目标，并加入实质数学延伸。共享对象、构造和引理使前后相关；依赖图记录一种有效参考组织，不能强制考生按该路线证明。有效短证明、合并定理和独立重证均应接受。增加字数、拆分原证明或堆叠互不相关小题不等于难度提升。

条件变化须在题面明确表达，不靠歧义或未说明的默认约定。可结合假设加强/放宽、量词顺序、点态/一致、有限/无限、受限域/原域、局部/整体、点相等/零距类、存在/取到、正向/逆向、标量/结构等变化。变化后真假混合；有些步骤确实可沿用前题。`turns` 的机制、预期真假、容易误用的前序结论及正确边界仅供出题侧使用，不进入候选消息，也不能据此要求候选猜作者意图。

所有阶段均列明精确条件、交付项、完整参考、具体必需证据和关键错误。数学构造的任意选择、极限交换、极值取到、反例的全部公理也在评分范围内。涉及多个结论的判定阶段，expected 表示整段合取的真值，required_evidence 必须逐个说明，不能把合取为假解释成所有分项都假。转折记录另用scope区分stage与subclaim，后者必须写出target_claim；其真假只属于该子断言。

## 输入、版本和执行

每题 `group_contract` 指向出题侧合同；它与参考、rubric及其他评审文件一起参与题集散列，并禁止作为本题或其他题附件。候选只接收task及显式solver_files。附件可使用安全的相对目录；绝对路径、父目录穿越、大小写重复、文件/目录遮蔽及runner保留文件均禁止。目录投影本身不保证进程或网络隔离。

每次运行将合同原始字节复制到答卷目录的 `review-contract.json`，同时把散列写入run与record。后续修改题库不会改变旧运行的合同；合同删除、漂移或不匹配的审核绑定均拒绝。整个题组是一次独立请求、一个相关样本。可另作分阶段反馈实验，但必须另版本、另记录，不与无反馈整组试卷混合。

整章题给出完整原文与外部依赖，采用含证明autoformalization，不测未提供证明的发现能力。义务清单明确范围，不能事后增加隐藏目标。第2章34项（8组定义/表示、26证明义务），第3章92项（8组定义/表示、84证明义务），它们分别属于一份整章答卷，不能宣称126份独立题。候选自建共享定义、统一项目和逐项alignment表；替代表示必须证明与原文对应。

## 逐阶段审核

共享 `review-template` 产生全组审核及按顺序列齐的stages。每阶段记录：

- decision：pass / fail / partial / unresolved。
- assumption_fidelity、proof_validity、scope_accuracy及是否不必要地缩小范围。
- failure_category：none、mathematical、lean_compilation、problem_defect、response_format、execution、unresolved。
- inherited_from：实际导致本阶段失效的前序阶段；独立错误另记，无错误的阶段不能被列作错误来源。
- lean_status、declarations及具体notes；notes应指向答卷中的论证或缺口，不能只写“看起来正确”。

每阶段pass必须全部数学轴通过、无额外限制、无未处理错误。整组pass须所有必答阶段pass；任何漏项、语义漂移、未完成、未满足Lean要求均不能靠其他阶段得分抵消。权重只产生completed_weight诊断值，阶段未完整通过不给该阶段的完成权重；它不是独立能力样本或凭数字断定证明正确。可在notes记录部分进展，不能凭自报分数绕过门槛。

后题不因前题错误自动全扣：若独立重证完整且满足当前条件，可以通过；若只是以错误前提给出条件推演，则记录partial及其来源。数学有效但Lean编译未完成时，数学轴可为valid而该Lean阶段仍非pass。报告同时列根因与受影响项，不能把一个共享定义错误当作几十种独立推理失败。

题目缺陷标记不自动从分母删除。需要复核题面、版本与外部依赖后，单独给出处置记录及重算；原答卷与原始统计保持。服务错误不等于数学错误；题库来源公开也不证明候选从未见过。

## Lean 交付与证据

需Lean的阶段须按题面提交完整命名源码，不能以片段、改写补丁、作者实现路径代替。原样候选验证器编译依赖闭包并审核所有声明；无修补通过报告必须绑定同一答卷、请求和报告散列。每个通过阶段还须映射到本次提交文件中实际被审计的声明。明确允许直接复用背景定义的义务也可映射到被本次依赖闭包实际导入、散列绑定并审计的冻结背景声明；不强迫为了命名而重复包装。编译通过只完成形式层门槛；声明是否与当前数学目标等价仍需逐项审核。

整章合同冻结背景模块为immutable_input_files；同名提交覆盖一律格式失败。Main.lean是required_output_files，漏交会在编译前拒绝。所有自建模块必须共同可编译。允许标准逻辑公理propext、Classical.choice、Quot.sound；sorryAx、增加公理、未经证明的目标字段、绕过内核均不能成为有效证明。若项目整体编译失败，可保存局部数学判断和编译定位，但不能将整个工程判为通过。

整章合同的alignment_manifest_required还要求原答卷恰好包含一个`json filename=alignment.json`代码块。执行器按原始UTF-8字节冻结清单，核对case_id/version、全部义务恰覆盖一次、完成状态、表示说明、依赖ID和声明映射；缺失或格式不合格在编译前拒绝，声明不在实际审计清单中则不能取得有效通过报告。判卷再次从原答卷提取并核对清单及散列，通过项必须标为complete且所审声明与候选映射一致。标为incomplete的工程仍可能编译成功，但该义务不能被评审提升为pass。清单不能替代数学语义审核，也不能用参考证明路线限制合法替代解法。

作者Lean、候选Lean、AI数学审核和人工审定分别记录。旧题编译证据仅适用于旧源码及原覆盖范围，不覆盖新题组；整章背景编译也不覆盖目标章。当前新题版本不继承任何旧通过率，难度是否更有区分力须由新的受控试跑确认。
