# 源绑定外部答卷

组件0.2.0接纳用户交回、可核查数学内容而尚无完整原生运行材料的答卷，并允许显式采用一段已留档的完整C003轨迹。0.1.0原记录和验证条件保持兼容；benchmark仍为0.6.0，计分权重和数学判准不变。

`math-gauge.paper-observation-record/v1`单独记录来源，不通过CLI或Dot原生执行收据校验。模型标识按交包者原始声明保留；未提供的后台SKU、版本、原生请求、工具事件和封卷时间保持未知。AI数学评审、人审、运行核验为不同状态。

私库保存完整原答、操作摘要、逐判准原评、任务和量规来源、错误引用字节范围以及全部已返回工程。常规继承在新批次前选定，绑定旧原答、审核、分值和工程。用户观察后明确选择的旧C003须另绑采用清单，不伪称预选，不与新答择优或拼接。后续补交只增加明确来源，不改写原始文件。

每项状态分为有原文且已评审、确认无交付、证据未决。无交付计0，不据此断言数学错误；证据未决保留未知。操作者摘要中的物理请求和有效计次原样保留，缺少原生证据时不得推定纯系统排除。最多3次有效尝试，采用首次正常交付；正常数学错误不能触发重考。新独立观察不得伪称恢复原剩余额度。

0.2.0可将物理请求与有效尝试分列。排除项须绑定原证据及核定声明，区分用户确认的API故障与原生证据核实；不会因此补造运行认证。超时和最大输出耗尽仍计有效尝试。固定截止已写出的实际答文可按用户选定作为交回正文评阅，原生终态仍保持真实状态；没有终答时不从实验或工作文件合成答卷。

`paper_observations.py`负责来源和投影校验，`scoring.py`负责所有算术。相同输入生成MC／RMC／SMC与首次／允许非逻辑重试两种条件，共六份报告；使用当前固定分母及扣罚。未决项保留完整区间，主表列满分100内的已确认贡献。

公开只保存公有原答及评审、公有逐项视图和匿名合并报告；私有题文、标识、原答及内部路径保留私有。两库通过散列互相绑定。内容可靠率和目标达成率需要对新答按共同合同单独审核，不继承旧答的两率。

补审以独立`content-rates.json`绑定现行选定`record.json`、主成绩及两份方法政策；私库保存逐承诺与完整目标审核，共用`scripts/score_content_rates.py`复算。原记录的`content_rates_status=not_reviewed`保留封存当时的状态，补审后页面读取有精确来源绑定的独立汇总；不为添加两率重写原记录、主分、原答或运行资格。仅完全相同的原答、同源工程和共同目标合同可沿用对应旧判断，并保留复用核验依据。

C003要求实际初答和固定R1、R2、R3，末轮计分，无best-of或拼接工程。每份上限10800秒；三轮必须串行，各轮使用上一轮封存源码、原始对话和固定中性提示。空终答、工具工作文件和操作摘要不能拼成模型最终交付；缺失初答时，后续轮次保持阻塞。

显式采用旧轨迹时，`alignment-adoption.json`使用`math-gauge.paper-alignment-adoption/v1`，绑定用户选择散列、原记录、0.4.0政策、原工程及逐项审核，依次保留A1/R1/R2/R3原答、父子关系、模型对齐表、现场清单和实际Main导入闭包。私库保存选择原文；公开仅给散列。原初答完成数、三轮诊断、误报及回退判定逐字沿用，共享评分器重新聚合，后轮修复不回填初答。旧交付时间未认证的事实不因采用而升级。

核验不调用模型：

```sh
python3 scripts/records.py check
python3 scripts/records.py check --root ../math-gauge-private --public-root .
```
