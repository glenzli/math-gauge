# 源绑定外部答卷

组件0.1.0用于接纳用户交回、可核查数学内容而尚无完整原生运行材料的答卷。benchmark版本仍为0.6.0，计分权重和数学判准不变。

`math-gauge.paper-observation-record/v1`单独记录来源，不通过CLI或Dot原生执行收据校验。模型标识按交包者原始声明保留；未提供的后台SKU、版本、原生请求、工具事件和封卷时间保持未知。AI数学评审、人审、运行核验为不同状态。

私库保存完整原答、操作摘要、逐判准原评、任务和量规来源、错误引用字节范围以及全部已返回工程。继承结果必须在新批次前选定，绑定旧原答、审核、分值和工程；新答不能以旧结果补齐失败或未知项。后续补交只增加明确来源，不改写原始文件。

每项状态分为有原文且已评审、确认无交付、证据未决。无交付计0，不据此断言数学错误；证据未决保留未知。操作者摘要中的物理请求和有效计次原样保留，缺少原生证据时不得推定纯系统排除。最多3次有效尝试，采用首次正常交付；正常数学错误不能触发重考。新独立观察不得伪称恢复原剩余额度。

`paper_observations.py`负责来源和投影校验，`scoring.py`负责所有算术。相同输入生成MC／RMC／SMC与首次／允许非逻辑重试两种条件，共六份报告；使用当前固定分母及扣罚。未决项保留完整区间，主表列满分100内的已确认贡献。

公开只保存公有原答及评审、公有逐项视图和匿名合并报告；私有题文、标识、原答及内部路径保留私有。两库通过散列互相绑定。内容可靠率和目标达成率需要对新答按共同合同单独审核，不继承旧答的两率。

C003要求实际初答和固定R1、R2、R3，末轮计分，无best-of或拼接工程。每份上限10800秒；三轮必须串行，各轮使用上一轮封存源码、原始对话和固定中性提示。空终答、工具工作文件和操作摘要不能拼成模型最终交付；缺失初答时，后续轮次保持阻塞。

核验不调用模型：

```sh
python3 scripts/records.py check
python3 scripts/records.py check --root ../math-gauge-private --public-root .
```
