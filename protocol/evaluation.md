# 评测协议

## 任务类别与当前集合

runner 支持三类任务：determinate（确定性证明或反例）、alignment（原文与形式化一致性）、exploration（给定结构下的构造研究）。当前默认二十题全部采用 exploration，使输入类别不泄露主目标真假。历史三类题仍用于管线合同测试。

研究题可以提出事实上不可达的强目标，也可以要求一个成立但较弱的构造。不能预设“所有题都是反例题”，也不能因为题面写了“目标”就把它当成新增公理。完整的合法反例解决相应全称目标；正向构造贡献另记。真弱目标则需要完成所要求的论证，不能通过单纯拒绝或指出无关的强结论不成立来算完成。

Lean 编译成功只验证实际编码命题；alignment 任务还须核对原文、声明和依赖。未要求候选 Lean 的任务，不因缺少候选 Lean 判失败。

## 数据和提示边界

题集由 suite.json、sources.json、每题 case.json、task.md、reference.md 和 rubric.json 构成。solver_files 是可见附件清单；evaluator_files 是评审专用清单。参考、真假、来源、rubric、人工审核状态不进入模型请求。

可选 case.candidate_instruction 必须是字符串：缺省沿用旧版通用提示，空字符串表示不额外附加指令。当前二十题均为空，solver_files 均为空，prompt.md 必须逐字节等于 task.md。request.json 中的题号、版本、共同题型是传输元数据，不能被适配器扩展成额外解题提示。

题面给全实际公理、定义域和必要量词，只给主要研究结论；不能把缺失条件清单、中间引理、退化情形清单或解题路线提前喂给模型。评审者使用完整结构清单和反例核验，这些不属于候选材料。

公开材料可供透明复核，但不能保证模型在训练中从未见过。私有题须保持数据与输出边界。输入目录分离不是进程访问隔离；通用 command 适配器本身不限制绝对路径读取和网络。实际闭卷试验按 [隔离 CLI 流程](isolated-cli-runs.md) 执行并保存实测证据。

## 原始证据与版本

每次运行创建新目录，保留实际提示、所有有效答卷、启动失败、超时、工具条件变更、响应散列、题集及 runner 指纹、型号与设置。新模型运行前冻结题面、参考和评分依据；不根据答卷质量决定保留哪次样本。

工具条件不符合预定方案时，保留该样本及偏差。如果需要修复后另跑，应记录作出决定的时间及依据；新会话不得含前次答案反馈。曾有搜索的运行不能被事后称为闭卷，也不能和无检索样本合并计算。

评分绑定 response_sha256，回答改变后原审核失效。新发现可以接受，但须单独验证；不能改写事前参考，制造原先已经覆盖的假象。CLI 成功状态不等于数学答案正确，模型标签也不等于供应商身份已核验。

## 审核和结论

逐题记录 reviewer/reviewer_kind（human、ai、fixture），decision（pass、fail、partial、unresolved），assumption_fidelity，proof_validity，scope_accuracy，unnecessary_restriction，以及有依据的 notes 和 findings。

严格通过要求论证有效、条件忠实、范围正确且无不必要限制。诚实未完成与错误证明分开；一个正确旁支不能抵消对原目标的错误声称。

显式增加条件后证明的定理是合法条件化贡献；它本身不构成偷条件。但如果最终把它称为原任务完成、把新增假设改称题设、或从期望结论倒推新条件，就属于范围或前提漂移。只有证明自己的结果确实需要相应条件时，才可谈必要性；不能把证明方式的需求当成命题的需求。

合法构造商、完备化、双对偶、下半连续包、偏解、障碍类或局部提升都允许。审核重点是这些对象的结论是否被无依据地提升回原空间、原点值、全局代表、唯一选择或更强收敛。

参考中的长链条用于确认构造和依赖，不是强迫候选走同一条路线。接受有效短反例与替代证明；“没有被题面诱惑”不能作为扣分理由。构造贡献按内容审核，不按条数或篇幅量化。

## 审核状态和报告

所有当前题目均为 draft / human pending。AI 起草、Astra Max 独立数学复核、程序检查、Lean 核验、模型校准和人工审定分别记录。只有非 replay、题目已人工审定且回答经过 human 审核的记录，才具有协议中的正式模型比较资格；真实性与公平性仍需核实。

exploration 不生成统一总分。真假边界、条件漂移、错误强化、有效构造与诚实未完成分别呈现。单题单次不推断整体能力排名或稳定失败率。

在题面、参考、评分与运行条件预先冻结后，可以先进行 **AI 审核的暂定配对比较**，供后续人工验收。严格完成比例指完整解决原题义务的题数占所列分母，不是对证明长度、发现数量或不同任务的加权总分。完整题集比例、已裁决子集比例、任务类型和数学主题分层须分别标明；未运行、隔离不合格、环境失败和审核未决不得悄悄从完整分母消失。未完成全套时，不发布完整题集通过率。人审门槛与正式比较资格保持不变。

生成或修复 Lean 的任务，严格通过须同时具备冻结源码、真实编译、公理依赖检查和完整语义对应审核；作者参考的编译不能代替候选产物。纯文字证明题不追加候选 Lean 义务。相同数学母题的不同任务版本按相关样本列出，不能视作相互独立的题目。附件传输和候选源码合同分别见当前运行计划与候选 Lean 验收说明。

公开结果可发布经检查的题面、回答与审核；私有题完整输出可能还原题目，对外汇总须另行审核。当前工具只生成本地文件，不自动推送、发布或脱敏。
