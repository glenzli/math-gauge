# 评测协议 v0.1

## 三类任务

1. determinate：结论确定，要求证明或反例。truth 标签只在评审材料中。
   错误结论与不必要加强条件分别记录。MG-D003 有两个独立断言，二者均须处理。
2. alignment：同时核对自然语言、实际 Lean 声明及证明依赖。
   编译成功不能覆盖隐含加强假设、量词变换或构造义务缺失。
   当前六题有三题对齐、三题失配，全部设计为可以编译。
3. exploration：基础结构和研究方向固定，结论开放。
   参考文件给出经过核对的可达基线，不设唯一答案或“命中目标结论”分。
   人工逐条检查实际假设、构造良定性、论证、适用范围与贡献。
   有效反例、障碍定理及意外结论都可记录。猜想不计为已证明发现。

## 数据边界

一个题库由 suite.json、sources.json、每题 case.json、task.md、reference.md 和 rubric.json 构成。
solver_files 是作答可见附件的明确清单，evaluator_files 标出额外的评审专用文件（例如修复示例）。只有 task 和这些附件进入 request.json。
题型、题号和版本可见；参考解、正确标签、判分要点、来源说明和审核状态不自动提供给模型。
公开题已存在于公开资料中，因此这种输入隔离不构成“模型从未见题”的保证。

输入目录分离只是文件组织与传输边界，不是操作系统权限隔离。
command 适配器由操作者明确指定，runner 不限制该进程读取其他绝对路径或联网。
本版不应让具有全盘读取权限的代理直接参加私有题测试；私有阶段需配备受限执行器。
v0.1 不复制评审材料、不通过题面指定命令、不使用 shell 执行。

## 原始证据与版本

每次运行创建新的输出目录，不覆盖既有运行。保存实际发出的请求、stdout、stderr、
执行状态、响应摘要、题集摘要、runner 源码摘要、配置和时间。
命令适配器的模型标签由操作者提供，不自动验证远端供应商或模型身份。
适配器应自行记录可核验的模型版本、采样参数、实际 token 使用和费用；
第一版不伪造缺失的供应商数据。

评分记录绑定 response_sha256。修改原始响应后，后续报告会拒绝继续使用旧评分。
v0.1 不自动覆盖已存在审核记录；需要修订时保留原运行，建立明确的新评审版本。
第三类的 findings 仅记录本次审核接受的具体结果，不据条数评价数学深度。

## 判分

每题审核记录包含：

- reviewer 与 reviewer_kind：human、ai、fixture。
- decision：pass、fail、partial、unresolved。
- assumption_fidelity：clean、drift、unknown。
- proof_validity：valid、invalid、unknown。
- scope_accuracy：correct、incorrect、unknown。
- unnecessary_restriction：是否无必要加强条件。
- notes：证据与适用边界；findings：第三类接受的具体发现。

严格通过要求证明有效、条件忠实、范围正确且没有不必要加强。
诚实未完成不等于错误证明，也不算完成。一个有效旁支不能抵消对原目标的错误声称。
显式附加条件下的结果可以另行记录，不算原任务完成。
合法推导出的辅助结构允许使用，不能仅因构造了商或幂集就判为偷加结构。

报告将三类分开。只有非 replay 运行、人工审定题目和 human 结果审核全部成立时，
记录才具备纳入模型比较的资格；这仍需操作者核实运行真实性和公平设置。
replay、fixture 和 AI 审核不会生成正式模型比较成绩。
当前首批题全部为 draft / human pending，不自动生成榜单。

## 人工审定

每题先核查来源公开性、前提自洽、参考论证、边界、评分是否允许有效替代解。
对开放任务，先审基础设定与基线，再逐次审模型产出。
人工通过后，在有署名、日期和范围的审定记录基础上更新 case.json 的 human/status，
并递增题目或题集版本。AI 不代填人类署名。

## 对外结果

公开题可发布经检查的请求、响应和评审材料。私有题的完整输出可能还原题意；
本版 report 只生成本地工件，不会自动发布、上传或脱敏。
公开私有题统计前，需人工选择可公开字段，并说明外部无法独立复现的部分。
