# 运行证据与正式比较资格

本标准规定共享多轮 runner 如何把实际运行记录接入正式比较资格。评分公式、分母、八题选择和177槽位不变。运行证据审核与题目人工审定、答卷数学审核、候选 Lean 核验分别记录。

## 证据解决的问题

一个模型标签或一份配置只说明请求了什么。正式比较还需核对实际发送的消息与参数、实际返回的可观察型号信息，以及候选进程的文件、工具和历史边界。每项判断必须指向本次调用的原始材料。

软件核对散列、结构、取值、时间关系与引用是否一致；具名的人类运行审核负责判断外部材料的真实性、进程归属、工具能力和尝试披露是否充分。这是有来源的审核，不是对供应商内部权重或基础设施的密码学认证。无法观察到的后端信息保留为未知，不用请求参数、模型自述或操作者填写的标签补齐。

## 每份答卷的要求

| 范围 | 必需证据与判定 |
| --- | --- |
| 原始调用 | 绑定完整主计划、冻结 runtime、槽位、原始生成身份、全部尝试、实际消息、参数、响应和错误输出；不能只保存挑中的成功重试 |
| 后端信息 | 从本次调用的原始返回材料定位可观察的模型与推理配置，与预先冻结的请求逐项比较；缺失、矛盾或来源仅是请求回显时不能通过 |
| 预算 | 核对冻结的时间、输出上限及其他有效参数，保留实际执行记录；声明、转发与已确认生效分别处理 |
| 文件与进程边界 | 保存真实文件打开探测、父进程与实际 worker 的归属及权限证据；题面可读，参考、记忆、旧运行等受保护材料不可读；不存在的路径不能算拒绝访问成功 |
| 工具与会话 | 核验实际工具权限、事件与新状态；A1/A2/A3独立，后续只使用原题、A1及本分支历史；其他分支和判卷结果不得进入上下文 |
| 运行审核 | 审核者身份、时间、决定、逐项依据和原始证据引用齐全；AI、fixture及未决审核不能产生正式运行资格 |

有可读答卷后发生的超时或非零退出不自动等同数学错误，也不能触发挑选更好答卷的重试。是否具有可审核材料与充分运行证据分别判断。拒答、错误证明或未完成的答卷可以是有效运行样本，其内容得分仍按既有标准计算。

## 不可变记录、修订与继承

导入时复制并冻结显式列出的原始文件，只接受限定目录内的普通文件；拒绝路径越界和符号链接。导入不会启动候选模型，也不会用生成的材料覆盖原答卷。模板及其中尚未填齐的字段只是待审核输入。

运行审核采用追加快照。修改决定、补充证据或撤销先前通过必须生成新快照，保留上一版身份；不能覆盖历史记录。报告记录实际使用的审核快照和证据身份，旧报告可以按原快照重现。选择已被取代的快照时，结果标为historical，原资格支持的数值列为 `historical_formal_score`，当前比较的 `formal_score` 保持空值；不能隐去后来发现的问题。

自查答卷依赖其上下文来源。A1或本分支上一轮的运行条件不合格时，后续轮不能单独取得完整资格。跨运行复用A1/R1时保留原生成身份和审核来源，不重新生成、不把新审核当成模型纠错。

同一主计划合并时，重复引用相同的原始证据可以去重；不同生成、不同已存在的审核判断或不一致的证据身份必须显式处理，不能自动选择更有利的一份。证据缺失的旧运行仍可读取和暂定评分。

## 评分边界

逐槽位报告运行证据是否合格及具体缺项；各分项和总分继续检查数学裁决覆盖、题目人工审定、答卷human审核、真实原始候选Lean证据、非replay/fixture与题包缺陷。全部适用条件满足时才给出 `formal_score`。不满足时，已有内容审核可以产生明确标注的暂定分；未知贡献保留固定分母区间。

运行审核通过不会改变数学结论或提高内容分。数学审核通过也不会证明运行隔离有效。离线测试中构造的证据只验证程序的分支和约束，不能成为真实候选成绩或人工批准。

当前仓库仍没有本版基准的真实候选运行；题目均待人工审定。工程接入完成后，这些事实保持不变。实际运行需先冻结配置、预算和隔离方式，再按已有授权范围执行。
