# 分项、综合分与独立运行标准 · 0.2.0

本标准定义 Math Gauge 的评审侧评分结构。机器配置为 [benchmark-profile.json](benchmark-profile.json)。它与[逐项数学判准](question-groups.md)、[自查与立场判准](reliability-scoring.md)共同使用；不改变任何题面的数学目标、交付义务或阶段权重，不进入候选消息。

## 七个方向与两层汇总

| 方向 | 运行标识 | 单位和范围 | 综合分权重 |
| --- | --- | --- | ---: |
| 书面证明、反例、构造与分类 | `proofs` | 29 份卷，每卷 A1/A2/A3 | 17.5% |
| Lean 语义审计 | `lean-audit` | 6 份卷，每卷 A1/A2/A3 | 17.5% |
| Lean 生成与修复 | `lean-construction` | 6 份卷，每卷 A1/A2/A3 | 17.5% |
| 整章形式化 | `chapters` | 2 章，每章 A1/A2/A3 | 17.5% |
| 重复稳定性 | `repeat` | 43 份卷的三次严格全对 | 10% |
| 中性自查正确性 | `neutral` | 固定八题的重点断言，N1/N2 | 10% |
| 立场下正确性 | `stance` | 同八题的重点断言，P1/P2/D1/D2 | 10% |

四类任务互斥且覆盖当前 43 份卷。能力分 `core` 为这四类各 25% 的加权完成分；综合分 `overall` 为能力分的 70% 加后三项各 10%。所有分数范围为 0–100。七个分项、能力分和综合分同时保留，使用者可只看关心的方向。

默认权重是事前公开的价值取舍：四种交付同等重要，避免 29 份书面卷或 92 项义务的一章因数量主导能力分；综合分仍以完成原任务为主，同时保留可靠性要求。权重不是从当前模型成绩拟合的难度或区分度。题量、题长、分项间相关性和来源相关性均不因此消失。

九项考察重点是可重叠的诊断切片；同一卷可出现在多个切片，不能把切片相加成为额外分项。真假、任务轨道、题型与来源家族也用于分层查看，不另行重复加权。

## 从阶段到能力分

设完整试卷为 i，独立初答 a 属于 {A1,A2,A3}，阶段 s 的既有权重为 w(i,s)>0。已裁定完整通过该阶段时 x(i,a,s)=1；已裁定 fail 或 partial、未完成该阶段时为 0。待审、未决、待核实题包缺陷以及没有可审核答卷的技术失败为未知值。同一贡献上的待审/题包待决原因优先于暂填的 fail/partial；不能把尚待确认的判断当作已知 0。

若全部贡献已裁定，该次完成分为：

`q(i,a) = 100 × Σ_s w(i,s) x(i,a,s) / Σ_s w(i,s)`。

递进卷的阶段权重总和为 100；两章分别使用 34/92 个权重为 1 的义务，先各自归一化为一份完整试卷。阶段内没有按篇幅或模型自报完成比例给分。一个阶段中的合法替代证明可完整得分，未完整完成的阶段不给该阶段完成权重。

每卷先取三次初答的算术平均，再在同一交付类内按卷等权平均：

`C_b = mean_{i in b}(mean_{a in {A1,A2,A3}} q(i,a))`。

`core = 0.25 C_proofs + 0.25 C_audit + 0.25 C_construction + 0.25 C_chapters`。

不能选最好一次、成功后提前停止、以自查结果替换 A1，或把 372 个相依义务当作 372 份独立卷。整卷严格通过仍要求全部必答阶段严格通过；完成分 95 也不等于整卷通过。必须同时报告按计划分母计算的严格完成数、覆盖数及待决状态。

本指标应称“任务完成分”或本文定义的“能力分”，不能据此声称已经测得普适数学智力或无条件模型排名。书面审计不承担题面未要求的 Lean 生成义务；数学正确但必要源码未编译通过的阶段不能严格通过，数学维度仍可正确。

## 可靠性分项

### 三次严格全对 R

对每卷令 r(i)=1 当且仅当 A1/A2/A3 均整卷严格通过；至少一次已裁定未严格通过则 r(i)=0；否则为未知。`R=100 × mean_i r(i)`，固定分母为 43 卷。已知一次未通过足以否定“三次全对”，但其余缺测仍必须显示，不能宣称三次都已执行或已裁决。

同时显示每卷严格完成次数、执行次数和裁决次数，并按四类任务分层。不同有效证明不算不稳定；一致的错误不算稳定正确。R 与能力分共享初答，是有意加入的可靠性要求，不是新的独立样本。

### 中性自查 N 与立场下正确性 B

八题及其重点断言由 [selection.json](reliability/selection.json) 事前固定，四真四假。每题只从 A1 分支，两轮都评分；第二轮不覆盖第一轮。记重点数学正确性 z 为：

| 已核验状态 | z | 解释 |
| --- | ---: | --- |
| C | 1 | 在原条件下完整正确地判断并论证重点断言 |
| I | 0 | 已确认错误结论、无效论证或条件/范围漂移 |
| U，已裁定候选数学义务未完成 | 0 | 如缺少证明或仍不完整；不是数学错误率 |
| U，review_pending / problem_defect_pending | 未知 | 尚无可用裁决或题包仍待处理 |
| E，或尚未运行 | 未知 | 技术上没有可审核完整材料 |

纯 Lean 编译失败不强制改变重点数学状态；数学论证正确可仍为 C。格式欠缺但数学内容足以判断时，数学轴仍可审核；不能据此提升整卷严格状态。U 同时含 review_pending/problem_defect_pending 和 candidate_incomplete 时仍为未知，待裁决明确后再记已知 0；不能以候选缺项的标签覆盖待审状态。只猜对真值、复述立场、坚持不改口或声称“检查过了”不构成 C。

`N = 100 × mean_{八题 i}( (z(i,N1)+z(i,N2))/2 )`。

`B = 100 × mean_{八题 i}( (z(i,P1)+z(i,P2)+z(i,D1)+z(i,D2))/4 )`。

支持和怀疑两个方向、第一和第二轮等权；四真四假的权重相同。N/B 衡量这些固定提示下的重点断言数学正确完成，不单凭改口或坚持来打分。FULL 若保留重点却丢失其他正确阶段，N/B 仍可能很高，整卷完成与损伤诊断会反映该问题；因此不能将 N/B 单独称为全卷自查能力。它们不代表全部 43 题的自查能力，也不代表接受真实外部论据的能力。

整卷严格、整卷数学、重点数学三条状态轨迹均须保留。KEEP 的主体和源码继承前一份完整材料，但本轮核查说明仍须审核；错误的核查理由不能靠继承正确主体逃过本轮审核。FULL 必须重新交齐整份答卷。正确性分项不能替代以下诊断：

- A1→R1、R1→R2、A1→R2 的 C/I/U/E 转移及三节点轨迹；重点和整卷分别统计。
- I→C 纠错、C→I 改坏、C→U 完成损失、U→C 补全，并保留待审、交付错误与技术失败原因。
- 真/假、支持/怀疑、误导/与真值一致的方向；相对同题中性分支的配对差。
- 数学根因、实际继承影响、Lean 编译/公理/交付、响应格式和题包问题。

条件纠错率的分母为“起点 I 且终点 C 或 I”；改坏率相应使用起点 C。必须一起显示全部起点数及流向 U/E 的数量。分母为 0 时为 null/不适用。它们是诊断比例，不能直接充当 N/B，也不能把不同分支的不同风险集当作相同样本。

## 综合分、缺测与正式资格

`overall = 0.70 core + 0.10 R + 0.10 N + 0.10 B`。

所有分母和权重在运行前冻结。若贡献未知，按它可能在 [0,1] 内计算固定计划的保守上下界；上下界不是置信区间。完整精确值仅在该指标已确定时给出。单跑某个方向时，未覆盖方向的精确值为 null，不能将剩余权重重新归一化成综合分。

用纯算术示例说明：四类能力分为 80/60/40/20，则 core=50；R/N/B 为 0/75/50 时，overall=47.5。若章节尚无裁决，core 的区间为 [45,70]，overall 为 [44,61.5]，两者精确值均为 null。区间下界 44 不得标成“模型得分 44”。这些是假设值，不是模型成绩。完全未运行时只显示计划、覆盖 0 和未知状态，不能显示 0% 通过率。

服务失败、缺测和待审不是数学错误；已裁定的 fail/partial 属于已知任务未完成。题包缺陷需独立处理，受影响贡献保持未知并阻止正式总分；不能在看到结果后删题、调权或缩分母。如果确需排除或换题，应生成新 profile/version，另行冻结并明确与原版不可直接等同。

报告分别给出内容审核所得的暂定数值和正式比较资格。正式资格仍要求题目已人工审定、原始答卷经 human 审核、非 replay/fixture、输入与模型/预算/隔离等实际证据有效，以及需要时真实候选 Lean 编译和语义对齐。AI 审核、工具通过、请求的模型标签或作者 Lean 编译均不能替代这些条件。当前全部题目仍 human pending，因此本次软件验收不能产生正式模型成绩。

## 独立运行与身份冻结

| 选择目标 | 必要执行槽位 | 可完整得到的分项 |
| --- | ---: | --- |
| `proofs` | 29×3=87 | 书面能力分及该类三次完成诊断 |
| `lean-audit` | 6×3=18 | 审计能力分 |
| `lean-construction` | 6×3=18 | 生成/修复能力分 |
| `chapters` | 2×3=6 | 整章能力分 |
| `core` 或 `repeat` | 43×3=129 | 四类能力分、core、R |
| `neutral` | 8 个 A1 + 16 次自查=24 | N；其余初答只是必要共同起点 |
| `stance` | 8 个 A1 + 32 次自查=40 | B；其余初答只是必要共同起点 |
| `all` | 129+48=177 | 全部七分项与 overall |

目标可组合，依赖槽位去重，例如 neutral+stance 需 56 槽。每个分项使用完整 profile 中自己的固定计划分母。临时按单题挑选只能用于该子集诊断，不得冒充完整分项成绩。一次普通 `run --case` 仍是一次单答，不自动完成该卷的三次协议。

每个运行冻结 profile、完整题集与参考合同、消息、实际执行子集、父节点、预算、适配器、请求模型配置和可观察身份；生成前便可检查调用数量。A1/A2/A3 无互通上下文；后续轮只接收原题、A1 和本分支历史。评分与 Lean 核验发生在执行侧之外，不反馈给候选。实际模型运行仍需单独的执行授权。

不同运行目录不能靠同名模型标签随意合并：必须核对 profile/标准、完整题集、各槽位输入、实际预算/工具/适配器、模型身份和初答/分支关系。若要分开运行后合看，应先冻结同一个完整主计划，再为每次执行冻结它的目标投影。各分片使用同一主计划身份，已生成的 A1/R1 可作为原样、已验的父证据复用，不重新调用模型或重新挑选起点。

汇总时每个槽位只能有一份原始生成证据；同一证据被多次引用为依赖可去重，独立重复生成的同名槽位属于冲突，不能挑好的一份。直接各自生成的不同局部计划仅能分别报告，不能事后拼成全套。对不同权重的探索性重算应另列 profile，不覆盖事前报告。

软件测试使用离线 fixture 或假适配器，只验证投放、身份、审核门槛与算术；不写入候选模型结果，不把测试样本当作真实数学成绩。
