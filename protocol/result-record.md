# 正式结果记录合同

合同版本：`math-gauge.result-record/v1`。当前 benchmark 统一版本为 **0.6.0**，公开与私有是同一版本的不同范围。单题修订号、软件版本与评分政策版本作为组件身份记录，不另立私有 benchmark 版本。

## 留存与目录

仅在用户明确选定固定留档时保存正式记录。当前CLI固定快照由 `benchmark.json` 的 `selected_result_models` 与 `selected_result_record_ids` 登记，另有独立 Dot native harness 的选定结果。CLI档案使用本合同的record.json；Dot使用文末所列独立原生记录类型。日常运行使用被 Git 忽略的 `runs/`；中间稿、旧成绩、旧题与备选题不在工作树另设历史区，使用 Git 历史恢复。

正式公开档案位于 `results/v0.6.0/<model>/<record-id>/`，包含简短 README、`record.json`、原始答复、逐项评审、计分输入及必要工程。私有原题、原答和评审保存在私有仓库相同版本与记录号下；公开目录只保留私有部分的合并聚合。

记录应能脱离原临时目录阅读。引用本记录内的材料使用安全相对路径、字节数与 SHA-256。大型证据可外置，但须有稳定位置与完整性绑定；缺失必须明示，不能用旧绝对路径伪装为已经留存。原执行路径可以作为历史元数据，不能成为唯一恢复入口。

### 公开逐题成绩投影

当前公开档案附加 `public-task-scores.json`，通过通用 `evidence` 描述符绑定，不改变原始答卷、评审或计分输入。投影只复制共享评分器已留存的三口径、两运行条件报告中当前公开题的 `case_id`、`completion`、`strict_pass`、`response_sha256` 与 `review_sha256`；父报告哈希必须与合并聚合的 `source_bindings.private_report_sha256` 一致。私有题及额外逐题字段禁止进入投影。私仓核查同时验证投影与原完整报告逐项相等。

页面把 MC/RMC 的单题比例作为阅读提示，Strict 使用原 `strict_pass`，不把其底层 `completion` 当成二元通过分。未测保持未知，重跑只显示正式接纳记录。投影不产生公开集总分，不进行新候选调用或重新评分。旧档案缺少此可选附件仍可验证；新的单题页面要求此附件齐全。`scripts/score_current_records.py --project-public-tasks-only --private-root <private-root>` 只从现有报告生成公开投影；网站构建随后仅使用公开仓库。

## 每次运行的身份

记录 benchmark 版本、题文与评测规则身份、模型请求标签和实际可观察后端、推理设置、harness/适配器版本、系统提示、实际支持的参数、工具与网络条件，以及原生、broker、外层预算。未知值保留 `null` 和原因。显示名称、时间戳和散列本身不认证后端。

复用旧答时，同时记录当前评测版本、原执行版本和原证据身份；不修改旧答或伪称本轮新考。标准初答、独立重复、分支自查、连续对齐研究和操作续作分别标识。来源选择、固定分母与评分政策在正式记录中明确绑定。

## 原始返回与模型自评

1. 保存平台提供的完整最终答复，包括开头和结尾、自我判定、限制、不确定性、KEEP/FULL 标记、全部命名代码块及附件。保存实际发送的角色消息、可获得的响应事件与工具输出。隐藏推理不要求也不伪造。
2. 需要测量完整性自评的题型，未来候选返回明确给出 `complete`、`incomplete` 或 `uncertain`，说明针对整份任务、编译、格式或某个局部目标，以及已知剩余问题。这个要求必须在候选实际收到的版本化题面或提示中出现；纯书面题不因此新增 Lean 义务。
3. 整理字段 `self_assessment` 记录判断、范围和来源。来源为 `model_structured`、`extracted_from_original` 或 `not_available`。事后抽取必须绑定原文证据；引文以 UTF-8 字节区间、原答散列和原话核验。审阅者的结论不得填成模型自报。
已有 `alignment.json` 中逐义务的 `complete/incomplete` 也属于模型返回。保存原标记、原 `case_id/version`、总数与自报完成数，范围标为 `formalization_obligations`；从回复抽出时绑定原回复的字节区间。该范围不等于编译、格式或整份工程交付完整，审核结果不能覆盖模型原标记。

4. 未要求自评、没有自评、表述含糊、原文缺失分别记录。对编译或某个局部的肯定，不自动提升为整份任务 100% 完成；模型自报 complete 不等于评审核实 complete。

## 每轮交付和审核

逐轮记录父节点、原始答复、KEEP/FULL、继承主体、工程快照、入口与实际 import 闭包、对齐表、封卷原因和时刻。四道形式化题统一以选定初答阶段的封卷归档工程评分；回复内源码与工程分别留存，二者有差异时不拼接或择优。

`reviews/formalization.json`逐题绑定原响应散列、冻结题目合同、封卷清单、源码、允许的前置材料、编译及公理审计和逐项语义判断。通过项须指向审计中真实存在的声明；评审者对应与模型原对齐表分别标记。原数学审核绑定该审核文件和来源政策0.4.0，当前三评分聚合另绑定0.8.0，原始逐槽评审保留，工程复核另列。私有合并记录可用`formalization_evidence_location: public_archive`显式引用同模型同记录号的公开工程审核，核验时必须由调用者提供公开根目录，不允许档案路径自行跨仓库读取。

每轮审核分别报告：执行终态、交付完整性、原字节编译及公理检查、数学完成度、语义对应、自评准确性、修复与回退。审核结论绑定具体字节并注明 AI/human/fixture；AI 审核、编译证据和人工批准分别记录。未审核不填为错误或通过。

新工程运行按首次原生终态或固定截止中较早者停止写入后封卷，分别保存触发、停止与采集时刻。原生生成完成与 CLI 退出分开。父轮不满足该运行冻结的接续条件则后续为 blocked，不补造成功历史。

## 多轮轨迹与最终状态

固定保存初答与每一轮，使用最后规定轮次的实际交付；不选最好一轮、不取各轮证明的并集。逐轮列出核实完成、未完成与未知义务，计算相邻轮实际修复和回退；各分支只与自己的父节点比较。

轨迹摘要包括：计划/实际轮次、首次自称整份完成、首次核实整份完成、其后实际核查保持轮数、误报完整次数、最后一轮完成度、最后实际交付，以及停止原因。状态区分 `verified_complete`、`incomplete_stable`、`incomplete_changed`、`regressed`、`interrupted` 和 `unresolved`。达到 100% 仅指在已有审核中全部义务得到核实；有限轮稳定不构成未来永不回退的保证。文件不变只能说明字节不变。

固定三轮研究不因模型自称 100% 提前停止。失败、缺测和未决留在固定分母中，未知不改成数学零。已有真实正确成果、后续修复和自评错误按当前冻结评分政策分别处理。

经确认在规定输出预算内耗尽仍无可评阅答案，属于本次交付失败：交付完成度0、严格不通过，固定分母保留。原生stop事件不可得时保留操作者声明及证据缺口，不伪造事件。该判断不裁定原数学命题的真伪；基础设施故障、未执行和审核未决仍分别记录。

## 历史材料的适配

本次将现有材料整理为新记录形式是观察后的记录迁移，不冒称旧考试预先要求了新字段。完整原文可用时保留原字节并作有依据的抽取；原文或事件找不回时逐项标缺失。不得为补字段重新问考生，再把新回答写成原轮自评。新调用若另获授权，必须另记来源和轮次。

记录格式变化不改变数学目标、原始执行状态或人工审核状态。DeepSeek按随后获得的评分及固定留档授权纳入同一来源数学审核政策0.4.0；本次整理不新增候选调用。

## 非逻辑重跑的并行记录条件

按[接纳规则0.1.0](nonlogical-retries.md)，原单次与允许重跑分开留档。每个计划槽位含首次有效模型作答最多3次；有确证的纯系统故障不占次数，物理请求号与有效尝试号分开保存，最大输出耗尽仍计1次，采用第一次正常交付；原失败、原答、原分保持原样。追加`nonlogical_retry`记录、完整尝试序列、政策身份、独立计分输入和结果，不得以数学错误为由再试。两组使用同一固定分母和数学权重，报告写明次数、选择与来源缺口；观察后补入的声明级材料维持暂定状态。

## 独立原生Harness记录

### Claude Code外部CLI来源

选定的Claude Code档案继续使用`record.json`，将原始请求、启动参数、会话元数据、设置、事件流、事件接收时刻、实际题文和完整最终返回作为独立的原生来源绑定。`math-gauge.claude-code-native-evidence/v1`只作观察后的接纳适配，由`claude_code_evidence.py`单独核验；不得把原日志改装成Codex或AGY事件，也不放宽它们的既有校验。

原生首次成功终态必须在原截止内交付，并绑定完整最终返回的原字节。原生交卷、外层CLI退出和内层API调用分别记录：已成功交卷后的清理退出130或退出码未知不自动改成模型失败；内层工具/服务往返不是新增外层模型尝试。输出上限若按每次内层API调用生效，不能宣称它是整场总输出预算。

`math-gauge.claude-code-native-evidence/v3`补充原收集器未完全闭合的来源，不改写v1／v2原档。原元数据标为transient_error但无最终返回且已超过实际截止时，按交付失败计0、消耗有效尝试；不能仅凭该标签排除为纯系统故障。原生success但最终payload为空也按无交付处理。用户允许的最多3次有效尝试是上限，不要求用满；已结算失败不同于未测。

原收集文本若添加了标题等包装，v3保留它与原导入收据，同时绑定首个成功终态的完整payload、事件序号、接收截止位置、原时限及双方散列；计分只使用原生完整最终返回。未闭合的物理请求必须保留现有prompt、设置、事件、计时快照等原件及用户接纳依据；缺失request.json或闭合元数据不能补造，也不据此假定有终态、交付时长或纯系统排除。此类无交付快照与后续候选重试分别计次。

两种尝试条件的`attempt_condition_sources`可分别绑定`theorem_extension_inputs`与`background_check_inputs`。私有来源须逐题核对对应条件选定A1的原答散列；公开只投影不透明散列。首答失败后的研究题正常交付只能进入规则重试组，不能把后续答卷继承给首答组。交付失败的研究任务保留0分，不虚构B、R、忠实性或核心完成裁定。

工具设置与事件核查只证明所留配置和实际观察到的调用；没有独立的运行隔离探针时，`effective_sandbox_verified`保持false，并明确缺少该证据。原生回显的型号也不等于独立认证后端。收集器版本按实际批次分别记录，不用原导出计划的单个版本号覆盖不同收集器源码。原始导出计划与真实导入收据均保留，观察后为计分组合的索引不冒称实际执行过的统一计划。
