# 评分与多轮运行器的离线证据

本目录记录当前共享runner的工程验收，不记录真实候选答卷或成绩。作者 Lean 的编译与逐项语义证据仍在 [verification/author](../author/README.md)，不能互相替代。

[offline-acceptance.json](offline-acceptance.json)绑定实际测试使用的程序、测试和评分标准散列，保存命令、结果与范围。它覆盖分项计划、固定分母聚合、多轮历史、KEEP/FULL、重试锁定、同主计划证据复用、审核绑定及离线CLI整合。测试使用fixture、假适配器或可控的本地进程，不访问真实模型。候选Lean检查的负面及绑定测试不等于重编译作者源码。

本次收据记录67项专项测试全部通过；随后完整回归 `python3 -m unittest discover -s tests` 执行279项，其中262项通过、17项按可选环境跳过。题集validate、目录检查、协议与已有作者证据身份检查通过；题集散列仍为 `441497a658972186e2e48966041d2ed52bb822bb8533ee3bfbc695a9e14f4c91`。这些数字描述本次固定源码验收，不是候选通过率。

材料检查器 `python3 scripts/validate_protocol.py` 只复核收据和当前文件身份，不重新运行这些测试。实现或评分标准改变后，旧验收失效；`--refresh` 不能直接把旧测试变成新源码的通过证据。维护顺序为：修改后运行受影响测试，复核结果和当前输入散列，再保存新的验收记录，最后刷新协议包。全套runner回归仍按AGENTS要求执行。

离线验收证明程序按被冻结合同处理材料、身份与算术，不证明模型的数学能力。当前新入口尚无独立后端身份/进程隔离证据接入，所有formal_score保持null；真实执行前还须冻结实际配置、预算和隔离条件并得到运行授权。题目人工审定、答卷数学审核与候选Lean原样核验也各有独立门槛。

运行目录、真实答卷与临时测试输出保留在本地 `runs/` 或临时目录，本目录只保留当前工程验收与边界。固定八题、48条消息和177槽位的材料身份见 [protocol/reliability](../../protocol/reliability/README.md)。
