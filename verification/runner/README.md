# 评分与多轮运行器的离线证据

本目录记录当前共享runner的工程验收，不记录真实候选答卷或成绩。作者 Lean 的编译与逐项语义证据仍在 [verification/author](../author/README.md)，不能互相替代。

[offline-acceptance.json](offline-acceptance.json)绑定实际测试使用的程序、测试和评分标准散列，保存命令、结果与范围。它覆盖分项计划、固定分母聚合、多轮历史、KEEP/FULL、重试锁定、同主计划证据复用、运行证据导入、追加审核快照、来源资格、独立外部题包与原始提交导入，以及离线CLI整合。测试使用fixture、假适配器或可控的本地进程，不访问真实模型。候选Lean检查的负面及绑定测试不等于重编译作者源码。

当前十套专项共169项全部通过、0跳过，42份输入文件的身份及命令、结果逐项保存在收据和原始日志中。完整回归 `python3 -m unittest discover -s tests` 执行368项，其中351项通过、17项因可选环境未启用而跳过，见[完整回归日志](logs/all-tests.log)。题集、分类目录和协议核验通过；43份试卷、372项审核义务与目录身份保持不变。题集散列仍为 `441497a658972186e2e48966041d2ed52bb822bb8533ee3bfbc695a9e14f4c91`。这些测试描述固定源码的工程验收，不是候选通过率。

材料检查器 `python3 scripts/validate_protocol.py` 只复核收据和当前文件身份，不重新运行这些测试。实现或评分标准改变后，旧验收失效；`--refresh` 不能直接把旧测试变成新源码的通过证据。维护顺序为：修改后运行受影响测试，复核结果和当前输入散列，再保存新的验收记录，最后刷新协议包。全套runner回归仍按AGENTS要求执行。

离线验收证明程序按被冻结合同处理材料、身份与算术，不证明模型的数学能力。[运行证据接入](../../protocol/execution-evidence.md)逐项核对实际调用与隔离材料，另存具名人类来源审核；满足适用条件时可以开放formal_score。正向验收只在临时合成题集上构造批准与审核，验证正式分项可达及撤销后的历史重现，未修改当前43卷的人审状态。

负向检查覆盖请求回显代替后端信息、缺失进程或本次参考材料探测、来源字节/绑定篡改、工具权限漂移、跨分片重复会话/状态/请求、伪造人审标志、审核冲突及撤销。探测工具同时保存实际正例文件散列。已知未提交的本地失败无需伪造供应商回执；具有真实不符观察的拒绝审核可以保留原字节并撤销资格。

[外部 harness](../../protocol/external-harness.md)专项另检查移位后的独立控制器、完整附件与精确分支历史、评审字段隔离、包外完整计划、原始字节及命名源码提取绑定、锁定后重试拒绝、累计预算与缺测。外部导入在共享审核与报告入口继续标记 `external_import`；fixture不能变成模型结果，通用外部来源声明也不能通过现有本地进程证据合同取得正式资格。

当前真实候选调用和本次Lean编译均为0，没有可发布的真实正式成绩。实际执行前仍须冻结配置、预算和隔离条件；真实工具能力对照也需要相应运行授权。题目人工审定、答卷数学审核与候选Lean原样核验各有独立门槛。软件可核验材料一致性，外部材料真实性、进程归属及未披露运行的判断仍由具名审核者负责。

运行目录、真实答卷与临时测试输出保留在本地 `runs/` 或临时目录，本目录只保留当前工程验收与边界。固定八题、48条消息和177槽位的材料身份见 [protocol/reliability](../../protocol/reliability/README.md)。
